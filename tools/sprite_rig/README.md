# 主角動畫工具（sprite_rig）

用設計圖 `docs/art-reference/player-knight-concept.webp` 的原圖像素做主角動畫。外觀完全來自原圖，只有姿勢隨動作改變。審查標準見 `docs/animation-review.md`。

需要 Python 3 和 Pillow。所有指令都在專案根目錄執行。這個資料夾有 `.gdignore`，Godot 不會匯入。

## 指令

```bash
python3 tools/sprite_rig/export_walk.py
```

```bash
python3 tools/sprite_rig/checks.py
```

```bash
python3 tools/sprite_rig/inspect_parts.py /tmp/parts.png
```

```bash
python3 tools/sprite_rig/compare_sizes.py
```

```bash
python3 tools/sprite_rig/downscale.py
```

```bash
python3 tools/sprite_rig/extract_reference.py
```

| 指令 | 作用 |
|---|---|
| `export_walk.py` | 產生走路動畫：精靈圖寫到 `assets/sprites/player/knight_walk.png`；預覽 GIF、和設計圖的比對圖、頸部以上的目視檢查圖寫到 `docs/art-preview/player/` |
| `checks.py` | 自動檢查（`animation-review.md` §4.1、§4.3、§4.4 能量化的項目）。全部通過時結束碼為 0 |
| `inspect_parts.py out.png` | 把每個部件的切割範圍用顏色疊在 40px 圖上，用來確認切割 |
| `compare_sizes.py` | 設計圖（同方法縮小）、舊 50px、新 40px 同比例並排，寫到 `docs/art-preview/player/knight_40px_vs_50px.png` |
| `downscale.py` | 從 `native/` 重建定案尺寸的零件庫 `native40/`：區域平均縮小、吸附色盤、恢復描邊、清雜點、手工修補 |
| `extract_reference.py [out_dir]` | 從設計圖重建 50px 的原生零件庫 `native/`（縮小的來源）。平常不用跑，已存好的結果可以重現到逐像素相同 |

## 精靈圖格式：`assets/sprites/player/knight_walk.png`

- **尺寸已定案（2026-09-26），不可再改**：身體（腳底到頭盔頂）40px，羽飾高出頭盔 7–11px，含羽飾總高 47–51px。
- 504×224，每格 56×56，最近點取樣，不可縮放取樣。
- 由上到下四列：朝下（south）、朝右（east）、朝上（north）、朝左（west）。
  - 朝左用設計圖的「側面」，不是朝右的鏡像，所以兩邊都是右手持劍。
- 第 1 欄是站姿（和 40px 零件庫逐像素相同）；第 2–9 欄是走路循環 8 幀。
- 腳底對齊點：每格的 (28, 53)，也就是第 28 欄、第 53 列是腳底中心。正面踏向鏡頭的腳會低 1px，是刻意的。
- 預覽用每幀 0.1 秒。接進遊戲時，播放速度可以依移動速度調整。

## 檔案

| 檔案 | 內容 |
|---|---|
| `native40/*_clean.png`、`native40/palette.txt` | 零件庫（定案尺寸，所有動畫都用這份）：四個視角各自縮到身體剛好 40px，共用 40 色色盤 |

| `rig.py` | 骨架工具：仿射變換、部件繪製（正向搬移＋補空隙）、部件遮罩、身體墊底圖、破洞與雜點清理 |

| `walk_side.py` | 側面（朝右、朝左）走路：部件切割範圍、關節點、8 幀的腳步與全身動作 |
| `walk_fb.py` | 正面、背面走路：同上 |

| `checks.py` | 自動檢查；所有以像素為單位的門檻都從 `BODY_PX` 推算 |
| `inspect_parts.py` | 部件切割疊圖 |
| `compare_sizes.py` | 尺寸比對圖 |
| `downscale.py` | 50px → 40px 零件庫，手工修補清單在 `PATCHES` |
| `extract_reference.py` | 從設計圖還原原生像素 |

- 走路動畫四方向 × 8 幀，定案尺寸 40px，已輸出。
- `checks.py` 還有兩項沒過，等使用者決定。兩者都高於 85% 底線，原因都是原動作本來就有的遮擋，沒有改動作：

  - 東向第 6 幀的高光：38 點，待機 43 點，差 5 點，容許 4.3 點。擺動腿的膝蓋縮到腰甲下。
- 羽飾擺動時碰到頭盔、圍出封閉背景（正面 5 幀、東向 2 幀），使用者已接受。自動檢查不看頸部以上，改看 `knight_walk_head_check.png` 目視確認。

### 程式怎麼串起來

```
設計圖 ──extract_reference.py──▶ native/ (50px) ──downscale.py──▶ native40/ (40px 零件庫)
                                                                      │
                                                   sprites.py（載入、畫格、站姿、腿）
                                                                      │
                     rig.py（變換、繪製、遮罩、補洞）＋ limbs.py（膝蓋）
                                                                      │
                                   walk_side.py / walk_fb.py（每個視角一個骨架）
                                                                      │
                  export_walk.py（精靈圖、GIF、比對圖）   checks.py（自動檢查）
```

- `walk_side.SideRig(cfg)`、`walk_fb.FBRig(cfg)` 在建立時切割部件、建墊底圖。`frame(i)` 回傳第 i 幀的 `sprites.Frame`（像素字典）。檢查要用的頭部位置、靴子位置放在 `rig.debug`。
- 每個視角的設定是一個字典（`EAST`、`WEST`、`FRONT`、`BACK`）：部件切割（`parts`）、關節點、紋理取樣範圍。動作幅度的常數在各檔案上方，註明了 50px 時的原值。

### 座標與縮放慣例

- **兩種座標**：
  - 設定裡的座標一律是 `native40/` 零件庫座標。
  - 輸出畫格座標 = 零件庫座標 + (`CX - META[view]['cx']`, `GROUND - META[view]['feet']`)。`cx` 是身體中心欄，`feet` 是腳底列。
- **連續座標和像素索引不同**：關節點、多邊形用連續座標（像素中心是 +0.5）；`y >= 42` 這類是像素索引門檻。從別的尺寸換算時，邊界若落在像素中間，要看圖決定歸哪邊，不能直接四捨五入。
- **每個視角各自縮放**：設計圖四個視角的身體本來是 49、50、51、50px，所以各自縮到剛好 40px（比例 0.78–0.82，存在 `sprites.META[view]['scale']`）。
  - `downscale.py` 的 `BODY` 記錄 50px 時的頭盔頂列和腳底列。
  - 縮放時算一個來源框，讓頭盔頂正好落在整數列、腳底正好落在頭盔頂 +40 列。
  - 50px → 40px 的換算：`x' = x·s`、`y' = (y − 50px 頭盔頂)·s + 40px 頭盔頂`。
- **畫格**：56×56，腳底對齊點 (28, 53)。所有視角的腳底都落在第 53 列（踏向鏡頭的腳可以低 1–2px）。
- **頭盔頂的量法**：骨架切好的 helmet 部件中，第一列至少 4px 寬的那一列。直接找「最上面一列不是藍色」會誤判成羽飾的深色描邊。
- **設計圖的像素不是正方形**：每格約寬 4.0、高 4.4 個設計圖像素。還原後刪掉最重複的欄，讓寬高比和設計圖一致。

### 踩過的坑與做法

- **繪製用「正向搬移＋補空隙」，不要只用反向取樣**（`rig.Layer.render`）：
  - 每個原圖像素正向搬到新位置；新位置之間的空隙，才用 8 倍放大圖的反向取樣補（上下左右至少兩邊已有像素才補）。
  - 只用反向取樣時，40px 的 1px 細條和單點高光會斷掉或消失。
  - 兩個像素搶同一格時高光優先，否則旋轉或壓縮時 1px 的反光會被擠掉。
- **細線條不旋轉**：劍身旋轉後會變粗、變細、變亮。劍只跟著握劍的手做整數像素平移；劍尖會插進地面時，把劍往上提（劍柄被拳頭蓋住，看不出來）。
- **東向兩條腿的紋理來源對調**（`walk_side.EAST` 的 `near_leg`／`far_leg`、`near_boot`／`far_boot`）：
  - 原圖腿上的反光在左半邊，遠側腿會壓暗表現深度，壓暗後反光就消失。
  - 所以讓不壓暗的近側腿用有反光的那一塊。
  - `sprites.draw_leg_tex` 另外把原圖腿上的每個高光點正向放回新姿勢的腿上。
- **手工修補的座標**在 `downscale.py` 的 `PATCHES`：
  - 正面：面罩第 20–31 欄、第 15–20 列（奇數欄亮條，第 25 欄是中脊）；鎖子甲第 19–28 欄、第 36–39 列；羽飾與頭盔右角之間挖掉 (36, 11)。
  - 朝右：面罩第 22–28 欄、第 15–20 列。
  - 朝左：面罩第 1–7 欄、第 12–17 列。
  - 修補只改中間調，不動描邊、藍色和高光。
- **設計圖不規則格線的偵測**（`extract_reference.py`）：
  - 每個軸算相鄰像素的色差總和，當作「邊界強度」。
  - 用動態規劃找一組邊界，讓每格寬 3–6px、總邊界強度最大，並偏好接近 4.39 的格寬。
  - 每格取內部的中位數顏色。
  - 固定週期的方法（傅立葉估週期）在這張圖上會錯，因為 AI 生成的格線寬度不一致。
- **補洞用墊底圖層**：
  - 被披風、手臂、肩甲、頭盔蓋住的身體位置，用鏡射取樣補上鎧甲紋理，稍微壓暗當陰影（`rig.body_fill`、`rig.inpaint_reflect`）。
  - 整張墊底圖畫在最底層，部件移開時才露出來。
  - 不可畫在上層，否則會蓋掉原圖像素。曾經因此蓋掉正面的披風。
  - 正面的披風在身體後面，所以正面不在披風底下墊身體。
- **頸部縫隙**：側面和背面先在底層畫一份往下偏 1px 的頭盔，頭部往上延遲時就不會露縫。正面不能這樣做：多出的頭盔會和羽飾圍出封閉區。
- **收尾清理的順序**：先把斷開的細條末梢接回主體（`reconnect_specks`），再補小洞（`close_holes`）。順序相反時，接回去的像素可能圍出新的洞。
- **正面、背面的腿**：
  - 用 `rig.axis_map` 把原圖的腿條從髖部拉到腳踝，靴子只做平移。
  - 抬腳量取整數，靴子才保留原圖像素。
  - 原圖是待機的外八站姿，走路時要把腳收到髖部下方（`fleg` 的 `dest_x`）。
- **走路循環的相位**：第 0 幀是近側（正面是畫面左邊那條）腿落地；手臂和同側的腳反向擺動；擺動腳往中線靠的是第 5、6 幀。
- **環境**：
  - macOS 沒有 `timeout` 指令。
  - zsh 沒有 `PIPESTATUS`（要用 `pipestatus`）。
  - 在 shell 裡 `cd` 會改變之後的工作目錄，路徑一律寫絕對路徑。
  - Godot 編輯器開著時，會自動匯入新的精靈圖並產生 `.import`。

### 檢查為什麼會誤判、怎麼修的

| 誤判 | 原因 | 修法 |
|---|---|---|
| 身體高度量成 54px | 把羽飾的深色描邊當成頭盔頂 | 用骨架切好的 helmet 部件量 |
| 正面、東向出現封閉空洞 | 40px 時羽飾和頭盔只隔 1px，擺動時碰上，圍住的是背景，不是身體破洞 | 空洞只檢查頸部以下；頸部以上用 `knight_walk_head_check.png` 目視 |
| 靴子空隙一格都沒量到，改後又量出 5–6px | 起初只量雙腳都著地的幀，但這個循環每幀都有一腳離地；後來逐列量，抬起的靴子只和另一隻共用靴筒那幾列，靴筒比腳掌窄 | 用整隻靴子的左右範圍量站距 |
| 起伏門檻 2px 過不了 | 門檻是我自己訂錯的。50px 時同樣的動作也只有 1.4–1.7px；使用者的要求是至少 1px 看得出來 | 門檻改成 1px |
| 藍色、高光比例在 40px 容易超過 ±10% | 40px 的高光只有 30–65 點，少幾點就超過 10% | 使用者決定改成「±10% 或 ±4px 取較寬，任何一幀不低於 85%」 |
| 50px 時正面劍身的高光是 112% | 劍旋轉後重新取樣，劍身變亮變粗 | 劍只平移 |

### 做新動作的步驟

以「輕攻擊」為例，檔名自行替換。

1. **寫姿勢計畫**：在新檔案（例如 `tools/sprite_rig/attack_side.py`）的開頭寫下：
   - 關鍵幀、重心在哪、每個部位怎麼動（比照 `animation-review.md` §4.2 的逐部位要求）。
   - 對照設計圖的哪張動作小圖。設計圖上的位置約為：
     - 待機 (40–400, 755–840)、行走 (440–800, 755–840)、衝刺 (830–1160, 755–840)
     - 普通攻擊 (20–560, 870–975)、技能攻擊 (590–1160, 870–975)
     - 跳躍 (1200–1320, 755–840)、受擊 (1370–1490, 755–840)、蹲下 (1200–1320, 895–975)、倒地 (1350–1500, 915–975)
2. **判斷骨架做不做得到**：大角度旋轉、原圖沒畫到的面、雙手握劍，要先畫新零件（用 `native40/palette.txt` 的顏色）。新零件先和原圖比對、請使用者確認外觀，通過後才用。
3. **寫骨架**：
   - 部件切割沿用 `walk_side.EAST`、`WEST`、`walk_fb.FRONT`、`BACK` 的 `parts`。
   - 繼承或複製 `SideRig`、`FBRig`，只改 `frame(i)` 的姿勢。
   - 座標用 `native40/` 座標。
4. **確認切割**：`python3 tools/sprite_rig/inspect_parts.py /tmp/parts.png`，目視每個部件的顏色是否落在該在的位置。
5. **輸出**：
   - 仿照 `export_walk.py` 寫 `export_attack.py`。
   - 精靈圖寫到 `assets/sprites/player/knight_attack.png`，格子同樣 56×56、對齊點同樣 (28, 53)。
   - 預覽寫到 `docs/art-preview/player/knight_attack_*.gif`，比對圖和頸部以上的目視檢查圖也照著產生。
6. **自動檢查**：
   - 把新動作加進 `checks.py`，門檻用現有的 `px()`，從 `BODY_PX` 推算。
   - 攻擊的相鄰幀位移本來就大，另訂上限，也用 `px()` 表示。
   - 跑 `python3 tools/sprite_rig/checks.py`，結束碼要是 0。
7. **目視審查**：每一幀放大 6 倍，加上 3 倍整體看，依 `animation-review.md` 逐條確認。交件訊息照 §6 列出。

### 已知限制與骨架做不到的姿勢

- **大角度旋轉**：部件轉超過約 30° 會開始變形。過頭的揮砍、倒地要轉 90° 的身體，需要另畫零件或整格重畫；倒地的 90° 旋轉本身不失真，但披風、腿要重新擺。
- **雙手握劍**（格擋、彈返）：設計圖沒有，也沒有可用的手部零件，要先畫設計稿請使用者確認。
- **劍被身體遮住或換到身體另一側**：正面、背面揮砍時，劍在身體前後切換。現在的骨架每幀的圖層順序是固定的，要改成可以逐幀指定。
- **身體扭轉或轉身**：3/4 視角的轉身，無法用 2D 旋轉原圖做出來。
- **遠側手臂**：朝右時用近側手臂壓暗後的複製品代替；朝左時看不到（劍掛在背後，由劍的擺動代表）。
- **小尺寸限制**：40px 的高光只有 30–65 點、細條只有 1px，比例檢查和細節保留都比較敏感。
- **補洞底圖**：墊底圖是推測出來的紋理。部件移開的範圍很大時，會露出鏡射的紋理。
- **方向與節奏**：只有四方向；AI 無法播放動畫，節奏感一定要請使用者看。

### 如果從頭再做一次，怎麼更快

1. 第一步就從設計圖還原原圖像素，不要自己重畫角色。
2. 開工前先定案最終尺寸，就不用做 50px → 40px 的轉換，也不用重新推導一次參數。
3. 動作前先寫好審查清單和自動檢查，包括全身動作、姿勢語意（例如站距），不要等被糾正才補。
4. 繪製一開始就用正向搬移＋補空隙，細線條一開始就只平移，高光一開始就優先保留。
5. 一開始就把設計圖的動作小圖當姿勢目標，並先做部件疊圖工具（`inspect_parts.py`）。
6. 參數寫成有名字的常數並註明依據，不要散在程式裡當魔術數字。

### 走路的逐部位動作與量化目標

新動作要比照這張表，列出每個部位在該動作中怎麼動（`docs/animation-review.md` §4.2）。

| 部位 | 側面 | 正面、背面 |
|---|---|---|
| 腿與腳 | 腳跟先著地 → 全腳掌 → 腳尖蹬地；擺動腳要抬膝（最高約 4px）；步幅看得出來 | 支撐腳打直；擺動腳抬膝，朝鏡頭方向縮短，腳抬高 2–3px；落地的腳往鏡頭方向多踩 1px |
| 重心、骨盆 | 每步上下 1px（峰到谷 2px），下踩時最低；頭部實際起伏至少 1px | 左右移向支撐腳約 1px，每步上下 1px |
| 軀幹 | 身體前傾（約 4–6°，下踩時更深） | 肩膀反向傾斜約 2° |
| 手臂 | 和同側的腳反向擺動；遠側的手也要擺 | 一前一後，往前的手略低、往內收 |
| 武器 | 跟著手移動，角度大致維持；不可插進身體或地面 | 同左 |
| 頭 | 比身體慢一拍，微微點頭 | 比身體慢一拍，微微歪頭 |
| 披風、羽飾、圍巾 | 從根部往末端擺動，末端比根部晚一點（相位延遲）；根部固定，不可和身體分開 | 同左 |
| 循環 | 最後一幀接回第一幀要順；一個循環約 8 幀 | 同左 |

走路的姿勢量化目標（`docs/animation-review.md` §4.3 要求每個動作都要有這樣的目標）：

- 量化目標（身體 40px、靴寬 6–9px；50px 時的值依比例重新推導並驗證過）：
  - 正面兩腳中心相距約 8px，背面約 6px。
  - 兩隻靴子的空隙（以整隻靴子的左右範圍量）0–2px，不可重疊。
  - 擺動腳在空中時往中線靠 1px（第 5、6 幀）。

第 3 輪交件前自己抓到的瑕疵（之後列入 §4.4 的固定檢查）：
- 身體前傾、披風往後飄時，身體和披風之間露出背景縫。
- 補洞用單一顏色往外延伸，變成平坦的色塊，和周圍的斑駁鎧甲不同。
- 把補出來的身體畫在最上層，結果蓋掉了正面的披風，還多出一條橫條。
- 手臂往後擺時，劍尖插進地面。
- 羽飾和披風最細的 1px 末梢在擺動時斷開，浮成旁邊的小點。

#### 尺寸定案（2026-09-26）

使用者試玩後定案：主角縮小到身體（腳底到頭盔頂）40px，Boss 不放大，羽飾另計。這次任務的經過：

| 項目 | 做法與結果 |
|---|---|
| 縮放比例 | 設計圖四個視角的身體高度本來就不同（49、50、51、50px）。統一乘 0.8 會變成 39–41px，轉身時身高會跳，所以改成每個視角各自縮到剛好 40px（比例 0.78–0.82）。這和任務說明的「0.8 倍」略有不同，交件時已說明 |
| 零件庫 | 從 50px 零件庫重建 `native40/`：區域平均縮小 → 吸附原 40 色色盤 → 描邊恢復 → 清掉孤立雜點 → 手工修補（`downscale.py` 的 PATCHES）。沒有直接縮放 50px 精靈圖 |
| 手工修補 | 正面面罩重畫成 6 道直條（中脊最亮）、兩個側面面罩重畫成直條；鎖子甲改成規則的深淺網點；正面羽飾末梢縮小後黏到頭盔右角，挖回 1px 缺口，恢復 50px 的開口外形 |
| 骨架參數 | 所有像素單位的參數（關節、切割範圍、腿與靴子的取樣範圍、站距、抬腳、起伏、布料擺幅）用各視角的實際縮放公式推導，落在像素中間的邊界對照 40px 圖決定，再用 `inspect_parts.py` 疊圖逐一確認 |
| 自己抓到的問題 | ① 第一次量頭盔頂時把羽飾的深色描邊當成頭盔，改用骨架切好的頭盔部件量；② 40px 的 1px 細條與單點高光在反向取樣下會斷或消失，改成「每個原圖像素正向搬到新位置，再補內部空隙；兩個像素搶同一格時高光優先」；③ 腿部高光集中在遠側腿的紋理來源，遠側腿壓暗後高光消失，把兩條腿、兩隻靴子的紋理來源對調；④ 我寫的新檢查有兩個錯：起伏門檻誤設為 2px（使用者要求是確認至少 1px 看得出來），靴子空隙只量雙腳著地的幀（這個循環每幀都有一腳離地，所以一格都沒量到） |
