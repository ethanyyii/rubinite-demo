# Boss 動畫工具（boss_rig）

用設計圖 `docs/art-reference/veltharis-concept.webp`（2026-09-30 第三版：約 5.2 頭身、劍首到下巴、握在握柄上段；一排四個視角：正面、背面、朝右、朝左——設計圖的朝左不用；朝左的成品從朝右的圖層另外組，見「朝左」）做 Boss（Veltharis）的精靈圖。外觀來自設計圖，不花錢（不用 PixelLab）。審查標準照 `docs/animation-review.md`；進度與決定記在 `docs/art-progress.md`「Boss 動畫」。

需要 Python 3 和 Pillow（沒有 numpy）。所有指令在專案根目錄執行。這個資料夾有 `.gdignore`。

## 指令

```bash
python3 tools/boss_rig/reference.py
```

```bash
python3 tools/boss_rig/export_size.py
```

```bash
python3 tools/boss_rig/export_anim.py
```

```bash
python3 tools/boss_rig/checks.py
```

| `gait.py` | 印出走路每一張兩條腿的關節位置 |

## 精靈圖格式（`assets/sprites/boss/`，還沒接進遊戲）

列＝方向，由上到下朝下、朝右、朝上、朝左（**朝左不是朝右的鏡像**，見「朝左」）。腳底對齊點都是 (128, 208)。

| 檔案 | 一格 | 欄 | 每張停幾個戰鬥幀 | 接法 |
|---|---|---|---|---|
| `boss_idle.png` | 256×224 | 12 | 10 | 循環 |
| `boss_walk.png` | 256×272 | 20 | 緩步 4、快步 2 | 循環；每張 Boss 走 4px |
| `boss_walk_start.png` | 256×272 | 10 | 同走路 | 站姿 → 走路；播完接循環的第 6 欄（`anim_walk.START_JOIN`）。播的時候 Boss 已經在移動 |
| `boss_walk_stop.png` | 256×272 | 4 組 × 8 | 4 | 走路 → 站姿；四組依序是從循環第 0、5、10、15 欄停下來（`anim_walk.STOP_FROM`），走路結束時選離目前那一欄最近的一組（最多差 2 欄）。播的時候 Boss 已經停了 |

走路類的畫格比待機高 48 列（腳底以下多出來的）：朝上時拖著的劍朝鏡頭伸過來，畫在腳底線以下。

接進遊戲時要注意：Boss 常常從走路直接出招（`WALK → IDLE → ATTACK` 只隔一幀），那時不播停步，攻擊的起手要能從「拖劍」的姿勢開始（做攻擊時處理：橫斬的起手本來就是劍往後拉，和拖劍的姿勢接近）。

## 動畫的做法（2026-09-30，待機、走路、起步、停步）

**原則：定案的站姿像素用整數像素搬，不重新縮小。** 站姿是從手繪風的設計圖縮出來的，滿是細紋理；把稍微移動過的圖再縮一次，整身的紋理會重新取樣（每一張都在閃）。所以：

- **小動作（呼吸、布料擺動、走路的起伏、正面／背面的腳）**：把定案站姿切成圖層（`labels.py` 的零件分區），每個圖層用整數像素位移；接縫的地方重複或丟掉一列，不內插（`rig.warp`、`rig.row_table`、`anim_walk.piecewise`）。待機第 1 張就是定案站姿，逐像素相同。
- **真的要轉的肢體（側面走路的腿；之後攻擊的手臂、劍）**：從設計圖切零件，在工作解析度（4 倍）照關節旋轉、組好，再走同一個 `boss.stylize()`（`limb.py`）。每一張都重新縮，所以只用在本來就在動的部位。
- **底圖**（圖層移開後露出來的地方）：布料先沿著每一列鏡射自己（`rig.mirror_under`，保留紋理和破爛的下襬），再往外長 4px（`rig.grow_under`）；腿往上鏡射（`rig.extend_up`，被布蓋住的小腿）。底圖一律壓暗 0.8 倍（在上面那個零件的陰影裡；不壓暗的話複製到高光會閃一下）。靴子底下不放布料的底圖（下襬到不了那裡）。
- **走路的腿只有一個模型**（`gait.py`，側面）：步幅、腳在地上的時間、骨盆高度、腳掌的俯仰。側面直接照它擺腿；正面、背面把「往前的距離」乘 0.35 變成畫面上的高低（和主角一樣的縱深比例）。
- **拖著的劍是一個 3D 姿勢，四個方向各自投影**（`drag.py`，使用者 2026-09-30：「劍的透視四面記得做好」）：手垂在髖部外側稍後，劍從拳頭往後、往下伸到地面，往外偏 30°；劍尖在地上，所以斜度由手的高度決定。朝右：整把劍斜在身後，劍尖比腳底線低 10px（劍尖比手更靠鏡頭）；朝下：劍指向遠處，只看到 0.54 倍長、從髖部往外下方伸出披風外；朝上：劍朝鏡頭伸過來，幾乎全長，劍尖在腳底線下 33px。前後的縱深一律 0.35 倍（和腳一樣）。劍是設計圖的劍用仿射變換畫到指定的握點、劍軸、劍寬向量上，再 `stylize()`。
- **循環裡的劍只畫一次**：每張重畫的話劍的紋理會閃。循環用同一張劍圖，劍尖固定、握點跟著身體移動，用整數像素斜切（`anim_walk.shear_to`）；握劍的手臂也一樣。起步、停步時劍真的在轉，每張重畫。
- **前傾**（使用者：「重心要往前，身體微前傾」）：側面把腰帶以上的每一列照高度往前推（6°，頭約 8px）；朝下是胸口和頭低 3 列（腹部少 3 列），朝上是高 3 列——朝鏡頭傾和背向鏡頭傾在畫面上的樣子。
- **起步、停步**（使用者：「走路跟停下來的銜接也要做」）：一個片段是一串「狀態」（骨盆高度、扭轉、兩條腿、劍在站姿和拖劍之間的比例……，`anim_walk.Clip`），畫每一張的程式和循環是同一份，所以接點兩邊一定對得上。
- **每個零件晚幾張**（頭晚 1 張、披風下襬晚 2 張……）都用「第 i−k 張的值」算，待機的波形在最後兩張和第 1 張是 0，所以第 1 張所有零件都回到站姿。

### 朝左（2026-09-30，使用者：右手拿劍，朝左時手大部分被身體擋住、左手沒拿東西）

朝左不是朝右的鏡像。兩個側面都在「朝右的空間」裡組（同一個身體），朝左最後才鏡像（`side.py`）：

- **朝右**（劍在靠鏡頭的手）：劍和握劍的手臂畫在身體前面。
- **朝左**（劍在遠側的手）：劍畫在身體和披風後面；站姿時只有握在握柄上的拳頭和手腕從胸口前面露出來（定案站姿的前臂整條墊到身體後面）；靠鏡頭的左手臂空著垂下（`arm.py`，從正面的垂手切的上臂、前臂、拳頭，調亮 1.3 倍到和側面原本的前臂一樣亮），走路時前後擺。
- 拖劍時劍在遠側，劍尖比手**更遠離鏡頭**，所以畫面上比腳底線高 16px、看起來短一點（0.84 倍）；握劍的手完全被身體擋住。
- 設計圖自己的朝左也是「劍在靠鏡頭的手」，幫不上忙。
- 原本舉著前臂的那塊軀幹沒有圖，用它下方 14 列的鎧甲補（`side.TORSO_CLONE`）。

### 握劍的手（2026-09-30，使用者：朝右的拳頭歪掉、沒接好手臂、手臂扭曲；背面的拳頭是豎著的）

原因：劍的圖上帶著站姿那個握劍的拳頭，劍一轉拳頭跟著轉；手臂是一整張圖從肩膀拉到那個拳頭。改成：

- **拳頭屬於手臂，劍從拳頭裡穿過去**：重畫的劍都用去掉拳頭的版本（`drag.clean_sword`：拳頭那幾列換成握柄，護手旁邊的披風、手臂殘塊清掉）。
- **側面**：手臂有手肘（`arm.py`：上臂、前臂、拳頭各自照關節擺，拳頭在前臂的延長線上、大小不變）。循環裡手臂自然垂下（上臂往後 6°、前臂 12°）。起步、停步時手肘在「定案站姿的手肘」和「垂下的手肘」之間移動，前臂從手肘連到拳頭；中途前臂朝鏡頭，畫面上變短。
- **背面**：整條手臂用設計圖背面本來畫的垂手；拳頭換成「從拇指那一側看」的拳頭（拖劍時劍身從拇指那一側往後伸，所以從背後看到的是拇指側；用正面垂手的拳頭鏡像）。劍身畫在拳頭前面（朝鏡頭伸過來）、劍首在手臂後面。
- **正面**（使用者說這面是對的）：維持原樣，只把拳頭的位置改成手臂自己的拳頭所在處。

### 踩過的坑

- 圖層沒畫底圖就直接合成（只畫 `pix` 不畫 `under`）：呼吸時腰帶、靴子上方出現 1px 的透明橫線。靜止的圖層也要用 `Layer.all()`。
- 劍旁邊的零星火焰像素被分到披風：披風的底圖從那一點往劍底下長成一個菱形，劍一動就露出一塊紅色。`labels.absorb_islands` 把小於 12px 的孤島併進周圍的零件。
- 腿的多邊形下緣比腳底高 3 個設計圖像素：腳底最後一列被分到披風，抬腳時留在地上一條黑線。
- 披風的底圖長到靴子底下：抬腳後原地留下一塊橫條紋。底圖在下襬以下清掉。
- 側面腿的零件多邊形沿著腿後緣帶到披風的紅邊：轉動後變成腿上一條紅線。零件在後緣那幾欄去掉紅色像素（`limb.BACK_EDGE`）。
- 側面前垂布的底圖複製到金色吊飾，變成腿後面的金色橫線：側面改用一塊暗色的「兩腿之間」底布（`anim_walk._backdrop`），太亮或金色的像素換成那一列最暗的布色。
- 靴子照腳尖前 2px 的點轉（離地時腳跟抬起）：腳尖會戳進地面 1px。改成照腳尖轉（`gait.BALL`）。腳踝高度要照站姿量（16.27px），用 16 會低 1px。
- （第一版，提著劍走時）劍跟著骨盆整個下沉：骨盆最低時劍尖戳進地面。第二版改成拖劍，劍尖固定在地上。
- 側面前垂布整塊晚一張：骨盆和布之間出現 1px 的縫。布的上緣跟腰帶、下襬才晚一張。

- `drag.project()` 同時拿來投影「點」和「方向」：側面的投影有一個基準面的常數（握劍的手那個平面），套到方向向量上劍就被壓成一條直線。分成 `project`（點）和 `project_vec`（方向）。
- 側面起步時劍尖一路貼著腳底線，最後一張才跳到循環的位置（低 10px）：過渡的劍尖高度也要跟著比例內插。
- 劍的滾轉角（劍面朝哪）試過 −60° 到 70°：0°（劍刃朝下）側面看到整個劍面、背面只剩一條線；45° 以上相反。取 12°。
- 側面原本舉起來的前臂後面沒有身體的像素：用它下方 14 列的鎧甲補；前臂超出胸口前緣的部分直接清掉。
- 合成後「布料色」的像素在側面掉到站姿的 65–80%：拖著的劍和垂下的手臂橫在披風前面（遮擋，不是簡化）。細節量改成合成前量（劍重畫後的像素數、紅、金是站姿那把劍的 93–103%），合成後的數字只列出來。

- 劍的切圖帶著護手旁邊的披風、手臂殘塊（站姿時被身體擋住看不到）：劍一離開原位就露出一塊暗紅色的方塊。重畫的劍一律用清過的切圖；只有正面、劍還立在身前的那幾張用原切圖（那塊陰影剛好是拳頭和肩膀之間的手臂）。
- 背面把手臂換成「只到手肘」的圖層：手肘下面原本定案站姿有畫的一小段不見了，露出披風的底圖（一塊紅色）。定案的手臂照畫，前臂另外疊上去。
- 兩段骨頭的 IK（上臂、前臂等長不變）在手靠近肩膀時手肘會往後翹成雞翅膀：真實情況是手肘朝鏡頭（畫面上變短）。改成指定手肘的位置、前臂照畫面上的長度畫。

## 和主角（sprite_rig）不同的做法，為什麼

- **設計圖沒有像素格**：主角的設計圖是規則的像素格（約 4.0×4.4），可以還原成原生像素；Boss 這張的邊緣強度做自相關，哪個方向、哪個視角都沒有週期（`reference.py` 開頭）。所以不還原原生像素，改成「原尺寸切圖 → 工作解析度擺姿勢 → 一次縮到定案尺寸」。
- **工作解析度**：`boss.WORK = 4`，每個定案像素 = 4×4 工作像素。四個視角在設計圖上同一條地面線、同一個比例，所以**全部用正面的比例縮放**（正面王冠尖到腳底 657 個設計圖像素 = `4 × 身高` 列，`boss.sheet_scale()`）；側面的王冠尖刺畫得比較高，縮完也比較高。姿勢、合成都在工作解析度做（平滑取樣沒關係），最後 `boss.stylize()` 一次縮小。所有方向、之後所有動畫幀都走同一個 `stylize()`，外觀和色盤才一致。
- **`stylize()` 分三層**（`boss.py`）：
  - 底層：工作圖先中值濾波（`MEDIAN = 5`）再區域平均縮小。直接平均會把設計圖的紋理雜訊變成滿身斑點（試過：銳化、純平均、中值、中值加去孤點、取眾數，見 art-progress）。
  - 金色層（金邊、骨、劍刃的淺色邊）：工作像素是金色的比例 ≥ `GOLD_MIN = 0.35` 的定案像素改成金色（該格金色像素的平均）。
  - 紅色層（發光符文、面罩十字）：比例 ≥ `RED_MIN = 0.25`。
  - 然後吸附色盤、輪廓邊上來源多半是描邊的改成描邊色、清掉 1–2px 的孤點。
- **色盤**（`palette.txt`，48 色含描邊）：用 OKLab 找最近色；建色盤時分成灰、紅、紫、金四組各自中位切割，每組有最少格數（`GROUP_MIN`）。用 RGB 加權距離＋整體中位切割時，紫色（披風內層、毛領）被併進灰色（第一版設計圖：正面的紫從 8.5% 掉到 4.5%）。改了之後各組比例和設計圖接近，數字記在 art-progress。

## 檔案

| 檔案 | 內容 |
|---|---|
| `reference.py` | 設計圖切圖與清理（去背、封閉的背景空隙、地面、三把劍的火焰） |
| `ref/*.png`、`ref/ref.json` | 清好的原尺寸切圖與座標（`reference.py` 產生，可重現） |

## 座標

- 設計圖座標（sheet）：`reference.py` 的常數都用這個（切圖框、劍的輪廓、靴子、握點）。`View.to_work()` 換成某個視角的工作座標（含左右翻轉）。
- 局部座標（local）：`ref/<視角>.png` 自己的像素（＝設計圖座標減掉 `ref.json` 的 `origin`）。`labels.py`、`limb.py` 的多邊形和關節用這個；`rig.Layout` 換成畫格座標。
- 定案畫格：一般動作 256×224、腳底對齊點 (128, 208)；攻擊類 384×336、(192, 272)。工作畫格是它的 4 倍。
- 「身高」＝正面的王冠尖到腳底（`boss.HEIGHT`，使用者定 160px）。

## 清理的細節（`reference.py`）

- **去背**：背景是平的中灰 (40, 42, 46)，和背景差 16 以內、連到圖邊的算背景；再往人物四周較暗的光暈長（`grow_into_halo`：中性灰、亮度 22–50，近黑的描邊擋住）；每個視角用「欄的範圍」（在相鄰兩個人物最接近的欄切開：455、780、1108）加種子填充分開。
- **被圍住的背景**（披風破口、手臂和披風之間、王冠尖刺之間，洪水填充到不了）：和背景顏色接近的連通塊，≥ 60px（靠近下擺 110 列內 ≥ 30px），**而且**平均是中性灰（紅、藍都不超過綠 4）、有 5% 以上和背景幾乎一樣（差 ≤ 5），才清掉（`is_backdrop_patch`）。背面披風中間的深灰紫布和背景差不到 16，只用大小判斷時整塊被挖掉；它偏紫、幾乎沒有和背景一樣的點，所以加了這兩個條件。
- **地面帶**（腳底上方 12 列）：除了靴子、披風下擺和劍尖以外都清掉；腳底以下一律清掉（設計圖的劍尖插進地面，不留）。
- **劍**（`SWORDS`：正面、朝右）：
  - 劍刃的左右邊界每一列自動找：導引輪廓附近 8px 內最外側的「淺色」像素（刃邊是淺米色；火焰的光暈是飽和的紅，不算），±3 列取最寬，再加 2px 描邊。
  - 劍柄、護手、握劍的手是手描多邊形（`hilt`）。`zone` 裡除了劍刃、`hilt`、身體那一側（`body_edge`／`body_side`）以外都清掉。正面的清理範圍在拳頭以上是讓開的（手臂在那裡）；正面劍刃和右腿之間是披風（`blade_edge`：身體從劍刃邊緣開始），上面的火焰條紋用周圍非火焰像素的中位數補（`recolor`）。
  - 單獨的劍（含握劍的拳頭）存成 `ref/sword_*.png`，`ref.json` 記劍首、拳頭（`grip`）、第二隻手的位置（`lower_hand`，護手上方）、劍尖；之後做攻擊時當零件。

## 遊戲畫面（`--mock`）

用一次性的腳本在真正的遊戲場景裡把 Boss 的佔位圖形藏起來、把主角放在攻擊範圍邊上（`SWEEP_RADIUS + 8`），存 960×540 的畫面和兩者的腳底位置（`feet.txt`：名字、Boss 腳底 x y、主角腳底 x y、畫面寬高）。腳本跑完就刪了（不 commit）；要重做時照 `tests/sim/capture_player_sprites.gd` 的開頭寫：`arena.boss_manual = true`、設位置、`arena.boss_view.visible = false`、`arena.camera.snap()`、等幾幀、`get_viewport().get_texture().get_image()`。右上角的「F3 手動出招」是手動模式的提示。
