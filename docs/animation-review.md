# 動畫審查標準 v1.0

> 適用範圍：之後的每一段角色動畫（主角、Boss）。交件前逐條自審，有任何一項沒通過就不能交件；沒辦法驗證的項目，交件時要明講，不可寫「已確認」。
> 之後再被糾正時，除了修正被指出的地方，也要把新規則補進這份文件。
> 這些規則的由來是主角走路動畫的製作過程（被糾正多輪）。每一輪的完整經過、走路的具體數值與工具細節，在 `tools/sprite_rig/README.md` 的交接筆記。

## 1. 規則的由來

| 發生過的問題 | 對應的規則 |
|---|---|
| 自己重畫角色，外觀走樣又簡化 | 參考圖是規格，不是靈感；每個方向都要和參考圖並排比對（§4.1） |
| 只動腿和上下起伏，動作僵硬 | 每個動作都要全身參與，逐部位列出怎麼動（§4.2） |
| 沿用參考圖的待機站姿去走路，腳外八 | 參考圖的姿勢屬於待機；每個動作重新判斷重心和站姿（§4.3） |
| 數值憑感覺取中間，改了又被說太開 | 姿勢目標要量化，寫進自動檢查（§4.3） |
| 範圍、工具、尺寸都自己假設 | 開工前先確認（§3） |
| 自審只量容易量的東西，就說「確認過」 | 動作與姿勢要逐幀目視；程式量不到的要明講（§5） |
| 縫隙、平塗補洞、補洞蓋掉披風、劍插地、細條斷開、細線旋轉變亮、高光被擠掉 | 技術品質的固定檢查（§4.4） |
| 自己寫的檢查門檻訂錯、量法量錯，造成假警報或量不到 | 新檢查本身也要驗證（§5） |
| 正面格擋的劍混在深色鎧甲裡，看不到（第 0 批） | 武器要和它背後的東西有足夠對比，寫成檢查（§4.5） |
| 完美彈返和格擋的輪廓太像（第 0 批） | 不同動作的關鍵姿勢，輪廓差異要超過門檻（§4.5） |
| 攻擊起手與頂點站得太直，和待機、格擋太像（第 0 批） | 攻擊的站距與骨盆下降要量化並提高；和設計圖做同比例輪廓疊圖（§4.3、§4.6） |
| 躺姿用站姿轉 90°，讀不出是躺在地上（第 0 批） | 骨架做不出、設計圖有畫的姿勢，從設計圖還原原生像素（§4.6） |
| 自己寫的檢查拿被檢查的程式當標準答案，改了程式照樣過（第 1 批，自己抓到） | 檢查要用獨立的標準，並用刻意做錯的情況驗證（§5） |
| 移動類照預覽的 0.1 秒播放，站地腳會滑掉身體移動量的 50–70%；原地播放的 GIF 看不出來（第 3 批簡報，自己抓到） | 播放速度用「不滑步」算法決定，移動類的 GIF 在地面上實際移動（§4.2、§5） |
| 後退、反向側移原定「同一組倒著播」，頭和布料會從晚一拍變成早一拍（第 3 批簡報，自己抓到） | 反向的循環要正向產生（§4.2） |
| 使用者接受的不合格一直列成失敗，檢查長期停在結束碼 1，之後看不出有沒有退步（第 2 批之後） | 接受的項目寫成有紀錄的豁免（§5） |
| 交接的試做姿勢只量了頭，實際超出畫格 3–10px，接到設計圖還原的躺姿時腳跳 12–20px（第 4 批，自己抓到） | 接到比例不同的還原姿勢時，兩端的頭、軀幹、腳都要量，也要量畫格邊界（§4.4） |
| 細條（羽飾、圍巾、高光）轉到新角度，像素數跳 10–20%（第 4 批，自己抓到） | 每一幀都量細節，不只量關鍵姿勢；過渡比例或細條的彎法要能微調（§4.1） |
| 四階段循環的布料晚兩個階段，檢查分不出晚還是早；「布料還揚起」的檢查被身體傾斜騙過（第 4 批，驗證時抓到） | 延遲設計成量得出方向的；量部件要相對它所在的身體（§5） |
| 蓄力、突刺在正面／背面把劍轉成側向（為了輪廓好認），看起來像蓄力橫掃（第 3 批，使用者事後指出） | 四個面向是同一個姿勢，依透視畫出該有的樣子；不為了好認而各自轉部件（§4.3） |
| 蓄力的腳在四個方向都壞掉：側面腿被拉長貼地、正面腿碎掉、走路時兩腳黏在一起（第 3 批，使用者事後指出） | 腳不可超出腿長；量化目標要先和腿長一起驗算；寬站姿的移動步伐要控制兩腳距離的變化（§3、§4.3） |
| 蓄力第一次修正後自動檢查全過，使用者看了說沒修好：腿被身體、布料擋住，整張圖看起來只是一團，自審時沒看出腿是什麼形狀（第 3 批） | 腿要單獨畫出來（只畫腿，加上髖、膝、踝連線）逐方向、逐幀看（§5） |
| 骨架的腿骨比站著時髖到踝長 35% 以上，腳一離開髖的正下方，膝蓋就頂到和髖一樣高：側面畫成桌子、M 字（第 3 批第二次修正時找到） | 膝蓋不可高過髖；腿骨長度要和實際站姿的腿長一致（§4.3） |
| 同一個姿勢朝左的腿特別扁：零件庫的朝左髖關節點比朝右低 2.4px（第 3 批第二次修正時找到） | 同一個姿勢，朝左、朝右的腿高要一致；新姿勢先核對四方向的關節點（§4.3） |
| 正面後腳因透視在畫面上變高，骨盆又壓低，腿長變成 0，靴子浮在腰甲上（第 3 批） | 正面／背面每一條腿在畫面上都要看得到（§4.3） |
| 為了過輪廓差異檢查把上身歪 16°，看起來像要跌倒（第 3 批第一次修正） | 不可為了過檢查而扭曲姿勢；自然的姿勢過不了，就列出來請使用者決定（§5） |
| 蓄力移動（40px/s）一輪 0.2 秒，比一般走路（100px/s）的 0.27 秒還快，看起來像小碎步（第 3 批第二次修正，使用者指出） | 移動速度比一般走路慢的動作，步伐節奏不可比一般走路快（§4.2） |
| 朝左的腿糊成一塊、朝右正常：骨架對近側腿的畫法在兩邊不對稱（第 3 批，使用者指出） | 同一個姿勢的朝左、朝右要並排比，一邊好看另一邊也要好看（§5） |
| 朝左時持劍手在身體遠側，拳頭和劍卻從近側手臂移開後的空位透出來（第 3 批，使用者指出） | 遠側的東西要被身體擋住，補上的底圖也算身體（§4.3、§4.4） |

## 2. 共通的根本原因

1. **開工前沒訂驗收標準。** 外觀、動作、姿勢語意都是被糾正後才補上，而且每次只看最新一次糾正，結果矯枉過正。
2. **自審只驗容易量的東西。** 能用程式算的都做了；「自然」和「姿勢對不對」不好量就沒檢查，卻仍然說「確認過」。
3. **沒辦法播放動畫。** AI 只能看靜態幀，節奏感的判斷本來就弱，必須用其他方式補（§5），並請使用者看。
4. **沿用參考圖時，把姿勢也一起沿用。** 參考圖定義的是角色的設計，不是每個動作的姿勢。
5. **參考資料沒用足。** 設計圖上的動作小圖（行走、衝刺、普通攻擊、技能攻擊、受擊、蹲下、倒地）就是姿勢目標。
6. **衝突沒先問，範圍沒先確認。**

## 3. 開工前確認

- 交付物：只要預覽，還是要接進遊戲？輸出什麼格式（精靈圖、GIF）、放在哪裡？
- 工具：付費生成（PixelLab 等）要使用者同意；第一階段禁止。
- 尺寸：**角色尺寸已定案，不可再改**。
  - 主角身體（腳底到頭盔頂）40px，羽飾另計（高出頭盔 7–11px）。
  - 精靈格 56×56，腳底對齊點 (28, 53)。
  - 攻擊類（輕攻擊、蓄力、突刺、處決）用 88×72，腳底對齊點 (44, 61)。身體尺寸不變，只是容器變大（2026-09-27 定案）。
- 其他文件規格和參考圖細節衝突時，先說明取捨、請使用者決定，不要自己選。
- 方向數、左右能不能用鏡像、每個動作幾幀、播放速度。
- 找出參考資料裡和這個動作有關的全部內容，當成姿勢目標。
- 判斷骨架做不做得到。需要新零件或新設計（例如雙手握劍）時，先出設計稿請使用者確認外觀。
- **先驗算量化目標彼此相容**（第 2 批）：例如「兩步之內頭每步 ≤ 4px」對「揮完骨盆前移 ≥ 4、前傾 ≥ 8°」在數學上就做不到。目標衝突要在開工前提出，不要畫完才發現。

## 4. 審查標準

### 4.1 外觀一致性（每個方向都要做）

- 產出比對圖：參考圖、待機幀、每一幀，用同一個像素比例並排。
- 特徵逐項比對：
  - 頭盔形狀、面罩條紋方向（正面是直條）、頭盔兩側的角
  - 羽飾的形狀與飄向
  - 圍巾、肩甲、披風的形狀與垂在哪一側
  - 腰部鎖子甲、劍與持劍的手
  - 配色
- 待機幀和零件庫（`tools/sprite_rig/native40/`）逐像素相同。
- 細節量每一幀都要量，不只量關鍵姿勢：細條和高光轉到新角度會重新取樣，過渡幀的像素數可能比兩端都差（第 4 批）。
- 所有幀的顏色都在參考圖的色盤內。
- 比例和參考圖一致；原圖的像素不是正方形時要校正。
- 細節量不可明顯少於待機幀：藍色布料、亮色反光的數量，每一幀都要在待機幀的 ±10% 或 ±4px 之內（取較寬的），而且任何一幀都不得低於待機幀的 85%。
  - 這項在**零件合成之前**量，用來證明零件本身沒有被簡化（2026-09-27 定案）。
  - 合成後的數字照樣列出。因遮擋而低於門檻的幀（例如格擋時劍擋住圍巾、跪姿與躺姿時身體被壓縮），註明原因並附圖請使用者目視。
- 不可為了符合尺寸規格而簡化造型；有衝突先問（§3）。

### 4.2 動作：全身都要參與

- 每個動作開工前，逐部位列出這個動作裡每個部位怎麼動，交件時逐項對照。部位包括：腿與腳、重心與骨盆、軀幹、手臂（含遠側的手）、武器、頭、披風、羽飾、圍巾。走路的表是範例，在 README 交接筆記。
- 某個部位不動時，要寫出理由。
- 重心的移動要看得出來：起伏、前傾、下蹲、後仰。
- 頭比身體慢一拍。
- 披風、羽飾、圍巾從根部往末端擺動，末端比根部晚（相位延遲）；根部固定，不可和身體分開。
- 武器跟著握它的手，不可插進身體或地面。
- 循環動作的最後一幀要能順接第一幀；一次性動作（攻擊、受擊）要有預備、動作、收尾。
- **反向不可倒著播**（第 3 批）：延遲是照「上一張」算的，倒著播就變成照「下一張」，頭和布料變成早一拍。後退、往另一邊的側移要把腿的順序倒過來、延遲重算，另外產生。
- **慢的移動，腳也要慢**（第 3 批第二次修正，使用者）：移動速度比一般走路慢的動作，前進、後退的一個循環不可比一般走路短（一般走路 16 模擬幀）。每隻腳一輪要走的距離 ＝ 移動速度 × 循環時間；腿短、站得寬的姿勢維持不了斜站時，讓兩腳像走路一樣前後交替，不要用加快步頻、縮小步幅來湊。
- **移動時腳不可滑**（第 3 批）：每張停的模擬幀數 ＝ 站地腳每張往後移的距離 ÷ 程式每模擬幀走的距離（最少 2）。做不到時（例如縱深壓縮、腿太短）要算出會滑多少並明講。
- 姿勢以設計圖的動作小圖為目標。

### 4.3 姿勢語意：這個動作的重心在哪裡

- 參考圖的姿勢屬於待機動作，不可直接沿用到其他動作。每個動作都要重新判斷重心和站姿。例：走路時重心往前，腳要收到髖部下方，不可維持待機時外八、撐重心的站姿。
- 每個動作都要把姿勢目標量化（例如站距、靴子空隙、前傾角、抬腳高度）：
  - 以 `BODY_PX` 的比例寫進 `checks.py`，不要憑感覺取中間值。
  - 走路的數值在 README 交接筆記。
- 每個方向分開檢查。一個方向做對了，不代表其他方向也對。
- **四個面向是同一個 3D 姿勢**（2026-09-28，使用者）：依透視畫出每個方向該看到的東西。例：劍指向前方時，側面看到整把平伸的劍，正面只看到朝鏡頭的劍尖，背面只看到握劍的手和劍柄。不可為了某個方向好認，就把部件在那個方向轉成別的角度；好認要靠姿勢本身（重心、傾斜、手的位置）。
- **腳不可超出腿長**（2026-09-28）：側面每條腿從髖到踝不可長於腿本身（近側 ≤ 1.0 倍，遠側畫在後面 ≤ 1.1 倍），否則腿被拉長、貼地。這個角色的腿從髖到踝只有約 6px 高，骨盆每壓低 1px，腳能伸出的距離就少很多；站距、骨盆下降量這類目標要先和腿長一起驗算。
- **寬站姿的移動**：步長由移動速度和每張停幾幀決定，兩腳距離會在「站距 ± 步長」之間變化；站距寬的動作要用較短、較快的步伐，讓兩腳不會黏在一起、也不會拉長。
- **膝蓋不可高過髖**（第 3 批第二次修正）：側面的膝蓋至少在髖下方「髖到踝高度」的 10%。膝蓋和髖一樣高時，腿會畫成桌子（一條水平的大腿加一條垂直的小腿）或 M 字。骨架的腿骨要和實際站姿的腿長相當，不可比髖到踝長很多（腿骨越長，腳一往前膝蓋就頂得越高）。
- **四方向的腿高一致**：同一個姿勢，朝左、朝右按住時髖到踝的高度差 ≤ 1.5px。零件庫四個方向的關節點是各自量的，新姿勢要先核對，不可假設一致。
- **遠側被身體擋住**（第 3 批，使用者）：側面時，在身體另一側的手、武器，只看得到伸出身體輪廓外的部分（例如往前伸出的劍尖）。手臂移開後補上的底圖也是身體，不可讓後面的東西從那裡透出來。
- **正面／背面每條腿都看得到**：往遠處的腳在畫面上會變高，加上骨盆壓低、走路抬腳，腿可能變成 0；每條腿在畫面上至少 2px，靴子不可貼在腰甲上。這個角色正面的腿只有約 5px，前後跨步和壓低都要先驗算。
- 攻擊的站姿不可和待機、格擋一樣直：要寬步、前腳屈膝、重心壓低。
  - 站距、骨盆下降量、前膝角度都要有下限，寫進檢查。
  - 目標和設計圖（例如 C2、C3、D2）的輪廓疊圖對照後再訂。

### 4.4 技術品質（寫成程式自動檢查）

- **破洞**：頸部以下不可有破洞或透光縫。被輪廓包住的透明像素不可多於待機幀。
  - 頸部以上的羽飾碰到頭盔、圍出背景，不算破洞，也不列入自動檢查。
  - 交件時附上頸部以上的檢查圖，請使用者目視。
- **雜點**：不可有 1px 的裂縫，也不可有 1–2px 的孤立雜點（待機幀沒有的）。
- **底圖**：部件移開後露出的地方要有底圖，質感要和周圍一致，不可出現平坦的色塊。
  - 底圖只能墊在最底層，不可蓋住任何原圖像素。
- **圖層順序**：必須正確。例：正面的披風在身體後面。武器在身體前後切換的動作，圖層順序要能逐幀指定。
- **邊界**：腳和武器不可穿過地面（往鏡頭踏出的腳可以低 2px 以內）；所有幀都在畫格內；各方向的腳底基準線一致。
  - 骨架姿勢接到設計圖還原的姿勢（例如躺姿）時，兩邊比例可能不同：頭、軀幹、腳在接點兩端都要量（第 4 批：躺姿的腿長 30%，只量頭會漏掉腳跳 20px）。
- **幀間位移**：不可有突然的跳動。每個動作要訂出相鄰幀的位移上限（走路是 4px），攻擊等快速動作另訂。
- **細線條與高光**：
  - 劍身、1px 的羽飾或披風末梢不可旋轉後重新取樣，只做整數像素平移；需要不同角度時，用原圖的顏色另外畫零件。
  - 1px 的細條和單點高光在移動、旋轉、壓縮時不可消失：用正向搬移像素，兩個像素搶同一格時高光優先。
- **門檻來源**：以上以像素為單位的門檻，都從 `checks.py` 的尺寸常數 `BODY_PX = 40` 推算。新動作沿用同一組常數，不另寫固定數字。

### 4.5 讀得出來：武器與輪廓（寫成程式自動檢查）

- **武器對比**：劍身要和它背後的東西分得開。
  - 量劍身核心和周圍 2–3px 的亮度對比，最弱的一段也要過門檻。
  - 劍身擋在深色鎧甲前時，可以加亮劍身，或把兩排都畫成亮面。
  - 最容易出問題的是正面格擋（劍橫在胸前）。
- **輪廓差異**：意思不同的兩個姿勢（例如格擋與完美彈返），不靠特效也要一眼分得出來。
  - 比較兩者的剪影（不含披風、羽飾），差異比例要超過門檻。
  - 門檻用「相似的姿勢」校準，例如走路相鄰兩幀；門檻值和依據都寫在檢查裡。

### 4.6 設計圖有畫的姿勢

- 凡是設計圖有對應姿勢的動作，交件時必須附同比例、同姿勢的對照圖（設計圖小圖和成品並排，並疊上輪廓），並在報告中說明和設計圖的差異。
- 骨架做不出、設計圖又有畫的姿勢（例如倒地），要從設計圖還原原生像素，縮到定案尺寸，不可用站姿旋轉代替。

## 5. 審查方式

- **逐幀目視**：每一幀都要看，兩種倍率都要。放大 6 倍以上看細節，遊戲實際倍率（3 倍）看整體。
- **分方向產出**：每個方向單獨產出 GIF 和幀序列圖。
- **動作自然度**：不能只靠靜態圖判斷。
  - 列出逐部件的動作表：每幀的前傾角、手臂擺角、頭部延遲、兩腳的位置。
  - 對照 §4.2、§4.3 逐項確認。
  - 需要時加上洋蔥皮（前後幀疊在一起看）。
- **自動檢查**：§4.4 和量化目標寫進 `tools/sprite_rig/checks.py`，每次修改後重跑。
- **驗證檢查本身**：
  - 新檢查要先拿已知的情況試：該過的要過、該抓的要抓得到。
  - 輸出實際量到的數值，不能只印通過或失敗。
  - 一項檢查一個都量不到（例如條件從未成立）時，這項檢查本身就是錯的。
  - 標準答案不可從被檢查的程式讀取（例如拿動畫程式裡的延遲表去比對動畫的延遲），否則改了程式檢查也照樣過。要用獨立的標準：動作本身的其他部位、文件定案的數字（第 1 批）。
  - 量部件的位置、起伏時，用部件合成前的像素，不要用看得到的像素：被別的部件蓋住一排就會量錯（第 1 批）。
  - 量一個部件（例如布料揚起）要相對它所在的身體量，不要量絕對位置：身體同時在動（傾斜、下沉）時會被騙過（第 4 批）。
  - 循環的延遲要設計成量得出方向的：四階段循環裡晚兩個階段和早兩個階段一樣（第 4 批）。
  - 位移量螢幕上看到的位置：程式在動作中移動角色時（攻擊前進），要把畫面的移動算進去（第 2 批）。
- **移動類的預覽**（第 3 批）：GIF 照程式速度在地面上實際移動（畫地面格線），滑不滑直接看得到；原地播放看不出腳滑。
- **接受的不合格寫成有紀錄的豁免**（第 3 批決定 10）：記下使用者核准時的實測值和決定編號；豁免的項目照樣印出數值，超過紀錄就重新失敗。檢查不可長期停在結束碼 1。
- **朝左、朝右並排比**（第 3 批）：兩個側面的骨架、零件庫都不對稱（關節點、靴子長度、近側是哪條腿），同一個姿勢要把兩邊放在一起看；一邊好看另一邊不好看，就找出差在哪裡，照好看那邊的畫法改。
- **腿要單獨看**（第 3 批第二次修正）：只畫腿的部件，加上髖、膝、踝的連線，放大 8 倍以上，四方向逐幀看。整張圖裡腿被身體、布料、劍擋住，常常只看得出一團。
- **不可為了過檢查扭曲姿勢**：檢查數字過不了時，先確認是姿勢真的不對，還是這項檢查量不到真正的差別（例如輪廓檢查看不到身體前面的劍）。自然的姿勢過不了，列出試過的做法，請使用者決定，不要硬加傾斜、轉動部件來過關。
- **明講限制**：沒辦法驗證的項目（例如實際播放時的節奏感）要在交件訊息裡明講。
- **舉一反三**：被糾正時，要檢查同一類問題有沒有出現在其他方向、其他部位。

## 6. 交件條件

- §3 都已確認，§4.1–§4.6 全部通過；沒通過的項目要有使用者的明確決定。
- 交件訊息要列出：
  - 通過了哪些檢查（附實際數值）
  - 哪些項目沒辦法驗證
  - 和文件規格不同的地方
  - 頸部以上的目視檢查圖
  - 設計圖有對應姿勢的：同比例、同姿勢的對照圖，以及和設計圖的差異（§4.6）

## 7. 驗證有效的做法

程式、零件庫和細節在 `tools/sprite_rig/`，用法和交接筆記見該資料夾的 `README.md`。

- **外觀來自原圖像素**：從設計圖還原原生像素，不自己重畫角色。還原時要偵測不規則格線、校正非正方形像素、去背、統一色盤。
- **定案尺寸的零件庫**：每個視角各自縮到身體剛好 40px。
  - 縮小用區域平均加吸附色盤。
  - 面罩、鎖子甲這類辨識度高的細節，用記錄在程式裡的手工修補補回。
- **骨架動畫**：
  - 部件用零件庫像素，只改位置和角度。
  - 腿用原圖腿部的紋理貼到新姿勢，高光點另外放回。
  - 補好的身體墊在最底層。
- **像素保留**：正向搬移每個原圖像素，再補內部空隙；兩個像素搶同一格時高光優先；細線條只平移。
- **輔助圖**：
  - 部件切割疊圖（`inspect_parts.py`）。
  - 和參考圖同比例並排的比對圖。
  - 頸部以上的目視檢查圖。
