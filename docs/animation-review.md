# 動畫審查標準 v0.3

> 適用範圍：之後的每一段角色動畫（主角、Boss）。交件前逐條自審，有任何一項沒通過就不能交件；沒辦法驗證的項目，交件時要明講，不可寫「已確認」。
> 之後再被糾正時，除了修正被指出的地方，也要把新規則補進這份文件。
> 這些規則的由來是主角走路動畫的製作過程（被糾正多輪）。每一輪的完整經過、走路的具體數值與工具細節，在 `tools/sprite_rig/README.md` 的交接筆記。

## 1. 規則的由來

| 發生過的問題 | 對應的規則 |
|---|---|
| 自己重畫角色，外觀走樣又簡化 | 參考圖是規格，不是靈感；每個方向都要和參考圖並排比對（§4.1） |
| 只動腿和上下起伏，動作僵硬 | 每個動作都要全身參與，逐部位列出怎麼動（§4.2） |
| 沿用參考圖的待機站姿去走路，腳外八 | 參考圖的姿勢屬於待機；每個動作重新判斷重心和站姿（§4.3） |
| 數值憑感覺取中間，改了又被說太開 | 姿勢目標要量化，寫進自動檢查（§4.3） |
| 範圍、工具、尺寸都自己假設 | 開工前先確認（§3） |
| 自審只量容易量的東西，就說「確認過」 | 動作與姿勢要逐幀目視；程式量不到的要明講（§5） |
| 縫隙、平塗補洞、補洞蓋掉披風、劍插地、細條斷開、細線旋轉變亮、高光被擠掉 | 技術品質的固定檢查（§4.4） |
| 自己寫的檢查門檻訂錯、量法量錯，造成假警報或量不到 | 新檢查本身也要驗證（§5） |

## 2. 共通的根本原因

1. **開工前沒訂驗收標準。** 外觀、動作、姿勢語意都是被糾正後才補上，而且每次只看最新一次糾正，結果矯枉過正。
2. **自審只驗容易量的東西。** 能用程式算的都做了；「自然」和「姿勢對不對」不好量就沒檢查，卻仍然說「確認過」。
3. **沒辦法播放動畫。** AI 只能看靜態幀，節奏感的判斷本來就弱，必須用其他方式補（§5），並請使用者看。
4. **沿用參考圖時，把姿勢也一起沿用。** 參考圖定義的是角色的設計，不是每個動作的姿勢。
5. **參考資料沒用足。** 設計圖上的動作小圖（行走、衝刺、普通攻擊、技能攻擊、受擊、蹲下、倒地）就是姿勢目標。
6. **衝突沒先問，範圍沒先確認。**

## 3. 開工前確認

- 交付物：只要預覽，還是要接進遊戲？輸出什麼格式（精靈圖、GIF）、放在哪裡？
- 工具：付費生成（PixelLab 等）要使用者同意；第一階段禁止。
- 尺寸：**角色尺寸已定案，不可再改**。
  - 主角身體（腳底到頭盔頂）40px，羽飾另計（高出頭盔 7–11px）。
  - 精靈格 56×56，腳底對齊點 (28, 53)。
- 其他文件規格和參考圖細節衝突時，先說明取捨、請使用者決定，不要自己選。
- 方向數、左右能不能用鏡像、每個動作幾幀、播放速度。
- 找出參考資料裡和這個動作有關的全部內容，當成姿勢目標。
- 判斷骨架做不做得到。需要新零件或新設計（例如雙手握劍）時，先出設計稿請使用者確認外觀。

## 4. 審查標準

### 4.1 外觀一致性（每個方向都要做）

- 產出比對圖：參考圖、待機幀、每一幀，用同一個像素比例並排。
- 特徵逐項比對：
  - 頭盔形狀、面罩條紋方向（正面是直條）、頭盔兩側的角
  - 羽飾的形狀與飄向
  - 圍巾、肩甲、披風的形狀與垂在哪一側
  - 腰部鎖子甲、劍與持劍的手
  - 配色
- 待機幀和零件庫（`tools/sprite_rig/native40/`）逐像素相同。
- 所有幀的顏色都在參考圖的色盤內。
- 比例和參考圖一致；原圖的像素不是正方形時要校正。
- 細節量不可明顯少於待機幀：藍色布料、亮色反光的數量，每一幀都要在待機幀的 ±10% 或 ±4px 之內（取較寬的），而且任何一幀都不得低於待機幀的 85%。
- 不可為了符合尺寸規格而簡化造型；有衝突先問（§3）。

### 4.2 動作：全身都要參與

- 每個動作開工前，逐部位列出這個動作裡每個部位怎麼動，交件時逐項對照。部位包括：腿與腳、重心與骨盆、軀幹、手臂（含遠側的手）、武器、頭、披風、羽飾、圍巾。走路的表是範例，在 README 交接筆記。
- 某個部位不動時，要寫出理由。
- 重心的移動要看得出來：起伏、前傾、下蹲、後仰。
- 頭比身體慢一拍。
- 披風、羽飾、圍巾從根部往末端擺動，末端比根部晚（相位延遲）；根部固定，不可和身體分開。
- 武器跟著握它的手，不可插進身體或地面。
- 循環動作的最後一幀要能順接第一幀；一次性動作（攻擊、受擊）要有預備、動作、收尾。
- 姿勢以設計圖的動作小圖為目標。

### 4.3 姿勢語意：這個動作的重心在哪裡

- 參考圖的姿勢屬於待機動作，不可直接沿用到其他動作。每個動作都要重新判斷重心和站姿。例：走路時重心往前，腳要收到髖部下方，不可維持待機時外八、撐重心的站姿。
- 每個動作都要把姿勢目標量化（例如站距、靴子空隙、前傾角、抬腳高度）：
  - 以 `BODY_PX` 的比例寫進 `checks.py`，不要憑感覺取中間值。
  - 走路的數值在 README 交接筆記。
- 每個方向分開檢查。一個方向做對了，不代表其他方向也對。

### 4.4 技術品質（寫成程式自動檢查）

- **破洞**：頸部以下不可有破洞或透光縫。被輪廓包住的透明像素不可多於待機幀。
  - 頸部以上的羽飾碰到頭盔、圍出背景，不算破洞，也不列入自動檢查。
  - 交件時附上頸部以上的檢查圖，請使用者目視。
- **雜點**：不可有 1px 的裂縫，也不可有 1–2px 的孤立雜點（待機幀沒有的）。
- **底圖**：部件移開後露出的地方要有底圖，質感要和周圍一致，不可出現平坦的色塊。
  - 底圖只能墊在最底層，不可蓋住任何原圖像素。
- **圖層順序**：必須正確。例：正面的披風在身體後面。武器在身體前後切換的動作，圖層順序要能逐幀指定。
- **邊界**：腳和武器不可穿過地面（往鏡頭踏出的腳可以低 2px 以內）；所有幀都在畫格內；各方向的腳底基準線一致。
- **幀間位移**：不可有突然的跳動。每個動作要訂出相鄰幀的位移上限（走路是 4px），攻擊等快速動作另訂。
- **細線條與高光**：
  - 劍身、1px 的羽飾或披風末梢不可旋轉後重新取樣，只做整數像素平移；需要不同角度時，用原圖的顏色另外畫零件。
  - 1px 的細條和單點高光在移動、旋轉、壓縮時不可消失：用正向搬移像素，兩個像素搶同一格時高光優先。
- **門檻來源**：以上以像素為單位的門檻，都從 `checks.py` 的尺寸常數 `BODY_PX = 40` 推算。新動作沿用同一組常數，不另寫固定數字。

## 5. 審查方式

- **逐幀目視**：每一幀都要看，兩種倍率都要。放大 6 倍以上看細節，遊戲實際倍率（3 倍）看整體。
- **分方向產出**：每個方向單獨產出 GIF 和幀序列圖。
- **動作自然度**：不能只靠靜態圖判斷。
  - 列出逐部件的動作表：每幀的前傾角、手臂擺角、頭部延遲、兩腳的位置。
  - 對照 §4.2、§4.3 逐項確認。
  - 需要時加上洋蔥皮（前後幀疊在一起看）。
- **自動檢查**：§4.4 和量化目標寫進 `tools/sprite_rig/checks.py`，每次修改後重跑。
- **驗證檢查本身**：
  - 新檢查要先拿已知的情況試：該過的要過、該抓的要抓得到。
  - 輸出實際量到的數值，不能只印通過或失敗。
  - 一項檢查一個都量不到（例如條件從未成立）時，這項檢查本身就是錯的。
- **明講限制**：沒辦法驗證的項目（例如實際播放時的節奏感）要在交件訊息裡明講。
- **舉一反三**：被糾正時，要檢查同一類問題有沒有出現在其他方向、其他部位。

## 6. 交件條件

- §3 都已確認，§4.1–§4.4 全部通過；沒通過的項目要有使用者的明確決定。
- 交件訊息要列出：
  - 通過了哪些檢查（附實際數值）
  - 哪些項目沒辦法驗證
  - 和文件規格不同的地方
  - 頸部以上的目視檢查圖

## 7. 驗證有效的做法

程式、零件庫和細節在 `tools/sprite_rig/`，用法和交接筆記見該資料夾的 `README.md`。

- **外觀來自原圖像素**：從設計圖還原原生像素，不自己重畫角色。還原時要偵測不規則格線、校正非正方形像素、去背、統一色盤。
- **定案尺寸的零件庫**：每個視角各自縮到身體剛好 40px。
  - 縮小用區域平均加吸附色盤。
  - 面罩、鎖子甲這類辨識度高的細節，用記錄在程式裡的手工修補補回。
- **骨架動畫**：
  - 部件用零件庫像素，只改位置和角度。
  - 腿用原圖腿部的紋理貼到新姿勢，高光點另外放回。
  - 補好的身體墊在最底層。
- **像素保留**：正向搬移每個原圖像素，再補內部空隙；兩個像素搶同一格時高光優先；細線條只平移。
- **輔助圖**：
  - 部件切割疊圖（`inspect_parts.py`）。
  - 和參考圖同比例並排的比對圖。
  - 頸部以上的目視檢查圖。
