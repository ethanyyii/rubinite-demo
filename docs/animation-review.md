# 動畫審查標準 v2.4

> 適用範圍：之後的每一段角色動畫（主角、Boss）。交件前逐條自審，有任何一項沒通過就不能交件；沒辦法驗證的項目，交件時要明講，不可寫「已確認」。
> 之後再被糾正時，除了修正被指出的地方，也要把新規則補進這份文件。
> 這些規則的由來是主角走路動畫的製作過程（被糾正多輪）。每一輪的完整經過、走路的具體數值與工具細節，在 `tools/sprite_rig/README.md` 的交接筆記。

## 2. 共通的根本原因

1. **開工前沒訂驗收標準。** 外觀、動作、姿勢語意都是被糾正後才補上，而且每次只看最新一次糾正，結果矯枉過正。
2. **自審只驗容易量的東西。** 能用程式算的都做了；「自然」和「姿勢對不對」不好量就沒檢查，卻仍然說「確認過」。
3. **沒辦法播放動畫。** AI 只能看靜態幀，節奏感的判斷本來就弱，必須用其他方式補（§5），並請使用者看。
4. **沿用參考圖時，把姿勢也一起沿用。** 參考圖定義的是角色的設計，不是每個動作的姿勢。
5. **參考資料沒用足。** 設計圖上的動作小圖（行走、衝刺、普通攻擊、技能攻擊、受擊、蹲下、倒地）就是姿勢目標。
6. **衝突沒先問，範圍沒先確認。**

## 3. 開工前確認

- 交付物：只要預覽，還是要接進遊戲？輸出什麼格式（精靈圖、GIF）、放在哪裡？
- 工具：付費生成（PixelLab 等）要使用者同意；第一階段禁止。
- 尺寸：**角色尺寸已定案，不可再改**。
  - 主角身體（腳底到頭盔頂）40px，羽飾另計（高出頭盔 7–11px）。
  - 精靈格 56×56，腳底對齊點 (28, 53)。
  - 攻擊類（輕攻擊、蓄力、突刺、處決）用 88×72，腳底對齊點 (44, 61)。身體尺寸不變，只是容器變大（2026-09-27 定案）。
- 其他文件規格和參考圖細節衝突時，先說明取捨、請使用者決定，不要自己選。
- 方向數、左右能不能用鏡像、每個動作幾幀、播放速度。**拿武器、披風只垂一側這類左右不對稱的角色，朝左不能用朝右的鏡像**（2026-09-30，Boss）：鏡像會把武器換到另一隻手。
- 找出參考資料裡和這個動作有關的全部內容，當成姿勢目標。
- 判斷骨架做不做得到。需要新零件或新設計（例如雙手握劍）時，先出設計稿請使用者確認外觀。
- **新姿勢先四方向試畫**（2026-09-29）：40px 的頭盔佔身高將近一半、手臂只有 13px，「高舉過頭」這類姿勢可能在某些方向完全讀不出來。定案前先把關鍵姿勢四個方向都畫出來看。
- **關鍵姿勢的劍在揮劍面上**（2026-09-29，第三版）：過渡幀是兩端內插出來的，起手的劍離開這一刀的揮劍面（例如橫斬的起手把劍舉高），整條線就跟著彎（橫斬變成往下劈）。定起手、收尾時先想好劍走哪個面，出圖後看過渡幀走的線。
- **攻擊先算劍尖的路**（2026-09-29，第二版）：起手到接觸、接觸到揮完，劍尖在畫面上各走多遠 ÷ 每步上限 20px ＝ 至少要幾步；畫格的幀數不夠放就先縮短路線（起手不要拉得太後、接觸放在弧線中間），或把起手放在第一張（第 2 批決定 3）。
- **雙手握武器先在 3D 試**（2026-10-01，Boss 攻擊）：兩隻手在握柄上的順序（哪隻手靠護手）決定武器擺在哪一側時兩隻手都搆得到——靠護手的手那一側是順手的一側。起手、收尾擺到另一側時，先量手臂長度（每一幀），搆不到就換姿勢或讓一隻手放開，不要畫出拉長的手臂。武器穿不穿過身體（軀幹、肩甲、頭盔）也在 3D 逐幀量。
- **先驗算量化目標彼此相容**（第 2 批）：例如「兩步之內頭每步 ≤ 4px」對「揮完骨盆前移 ≥ 4、前傾 ≥ 8°」在數學上就做不到。目標衝突要在開工前提出，不要畫完才發現。

## 4. 審查標準

### 4.1 外觀一致性（每個方向都要做）

- 產出比對圖：參考圖、待機幀、每一幀，用同一個像素比例並排。
- 特徵逐項比對：
  - 頭盔形狀、面罩條紋方向（正面是直條）、頭盔兩側的角
  - 羽飾的形狀與飄向
  - 圍巾、肩甲、披風的形狀與垂在哪一側
  - 腰部鎖子甲、劍與持劍的手
  - 配色
- 待機幀和零件庫（`tools/sprite_rig/native40/`）逐像素相同。
- 細節量每一幀都要量，不只量關鍵姿勢：細條和高光轉到新角度會重新取樣，過渡幀的像素數可能比兩端都差（第 4 批）。
- 所有幀的顏色都在參考圖的色盤內。
- 比例和參考圖一致；原圖的像素不是正方形時要校正。
- 細節量不可明顯少於待機幀：藍色布料、亮色反光的數量，每一幀都要在待機幀的 ±10% 或 ±4px 之內（取較寬的），而且任何一幀都不得低於待機幀的 85%。
  - 這項在**零件合成之前**量，用來證明零件本身沒有被簡化（2026-09-27 定案）。
  - 合成後的數字照樣列出。因遮擋而低於門檻的幀（例如格擋時劍擋住圍巾、跪姿與躺姿時身體被壓縮），註明原因並附圖請使用者目視。
- 不可為了符合尺寸規格而簡化造型；有衝突先問（§3）。

### 4.2 動作：全身都要參與

- 每個動作開工前，逐部位列出這個動作裡每個部位怎麼動，交件時逐項對照。部位包括：腿與腳、重心與骨盆、軀幹、手臂（含遠側的手）、武器、頭、披風、羽飾、圍巾。走路的表是範例，在 README 交接筆記。
- 某個部位不動時，要寫出理由。
- 重心的移動要看得出來：起伏、前傾、下蹲、後仰。
- 頭比身體慢一拍。
- 披風、羽飾、圍巾從根部往末端擺動，末端比根部晚（相位延遲）；根部固定，不可和身體分開。
- 武器跟著握它的手，不可插進身體或地面。
- 循環動作的最後一幀要能順接第一幀；一次性動作（攻擊、受擊）要有預備、動作、收尾。
- **每一種進場都要驗證**（2026-09-29）：一個動作可能從好幾種狀態開始（連段最早接段、收招後半接段、待機中的接段寬限、格擋、慢步腿）。每一種到第一張都要在位移上限內；兜不攏時畫兩個版本的開頭，寫清楚遊戲裡依什麼條件選哪一個。
  - 下一段從接段幀開始，上一段最後顯示的是**前一幀**：從那一張（和之後每一張）量起（第三版）。接段的幀改了（例如拉長連段的間隔），來源就跟著換。
- **面向目標橫著走、往後退要另外做**（2026-09-30，Boss，使用者決定）：遊戲裡角色會面向目標側移或後退時，不可沿用往前走的循環（會變成腳往前走、人橫著滑或倒著滑）。步幅和節奏照同一個速度算（不滑步、步伐不比往前走碎）。
- **反向不可倒著播**（第 3 批）：延遲是照「上一張」算的，倒著播就變成照「下一張」，頭和布料變成早一拍。後退、往另一邊的側移要把腿的順序倒過來、延遲重算，另外產生。
- **慢的移動，腳也要慢**（第 3 批第二次修正，使用者）：移動速度比一般走路慢的動作，前進、後退的一個循環不可比一般走路短（一般走路 16 模擬幀）。每隻腳一輪要走的距離 ＝ 移動速度 × 循環時間；腿短、站得寬的姿勢維持不了斜站時，讓兩腳像走路一樣前後交替，不要用加快步頻、縮小步幅來湊。
- **移動時腳不可滑**（第 3 批）：每張停的模擬幀數 ＝ 站地腳每張往後移的距離 ÷ 程式每模擬幀走的距離（最少 2）。做不到時（例如縱深壓縮、腿太短）要算出會滑多少並明講。
- 姿勢以設計圖的動作小圖為目標。
- **狀態之間要有銜接**（2026-09-30，Boss 走路，使用者）：站著 ↔ 移動這類姿勢差很多的切換，要做起步、停步的過渡動畫，不可一格跳過去。過渡的第一張接得上來源、最後一張接得上目的（寫成檢查），並寫清楚遊戲裡怎麼選、怎麼接（從循環的哪幾張可以接停步、起步播完接循環的第幾張）。
- **武器在姿勢之間的路線要符合人體工學**（2026-10-01，Boss 起步，使用者）：兩個姿勢之間，武器走人真的會用的路線，不是兩端之間角度最短的內插——最短的路常常讓武器穿過手臂、肩甲或身體（Boss 把立在地上的劍扛上肩：劍尖從身側往後上方甩，劍身要穿過肩膀）。先想人怎麼做（劍尖往前、往上舉起來，立在肩前，再往後放到肩上），照那條路定劍的方向；揮動時刃在前（劍是刃先走的），放到肩上時手腕才把劍面翻平。路線變長時：畫格放不下就用大的容器（攻擊類的畫格），每張的位移仍在上限內，不夠就加長片段。
- **一招裡的轉身就是這一刀**（第四、五版，使用者）：砍到的那一下在轉身裡面（例如側身時伸直的劍掃過目標），轉完就停。轉身前另外蓄勢、轉完再換一張「面向目標出劍」的圖，或轉身整個放在起手，都會讀成兩個動作、中間像停了一下。
- **一次只動一隻腳，踏步配合揮劍**（2026-10-01，Boss 攻擊，使用者）：兩隻腳同時離開原位、髖又前後晃，看起來像跳起來。起手時腳不動，蓄力靠上身轉、劍舉起來；揮下去的時候踏出一隻腳、落地和砍到同時——踏哪一隻看劍的方向（Boss 從右肩往左下揮，踏右腳；第二刀從左肩往右下揮，右腳收回、換左腳踏出，兩步分開）；身體（含髖和腿）跟著踏出的腳轉一點。腿單獨畫出來看每一張是不是只有一隻腳在動。
- **踏步出招是弓步，重心跟著腳走**（2026-10-01，Boss 攻擊第四版，使用者）：踏出去的腳要比走路的半步遠（Boss 走路兩腳在髖前後各 24px，弓步踏 36px），髖跟著過去（在兩腳之間、靠前腳六成以上，Boss 約 2/3），上身前傾壓在前膝上（Boss 20°）。只把腳踏出去、髖還在兩腳中間，看起來重心沒動。砍到那一刻武器的高度在目標的高度裡（主角 40px）、長度到判定邊緣——前傾本來就是讓武器更低、更長的方法。
- **連段換腳是往前踏過去**（2026-10-01，Boss 雙斬，使用者）：第二刀換另一隻腳時，後腳直接往前踏過前腳（前腳不收回）。整招因此前進：遊戲在固定的幾幀把角色往前移（Boss：第二刀判定前 0.2 秒、28px，判定開始時已經踏完，判定期間不動，被彈開的動畫才接得上），美術照遊戲的位置畫（踩在地上的腳在地上不動），遊戲的數字和美術用的數字寫成檢查比對。正面／背面的縱深只畫 0.35 倍，遊戲往前移時踩著的腳在畫面上會滑一點（和走路一樣），這是這個視角本來就有的。
- **肩膀帶著上臂轉**（2026-10-01，Boss 攻擊，使用者）：揮動武器不是只有前臂在甩。每個姿勢要定手肘往哪裡：舉劍時手肘往外抬、揮過去時手肘跟著繞過去、揮完時伸直的手臂跨過身體或手肘往後；肩膀跟著上臂聳起（抬手）、往前（往前伸）；肩甲蓋在上臂上，跟著上臂轉。只靠 IK 讓手肘自然往下垂，上臂會一直藏在肩甲下或指著鏡頭，看起來像肩膀不動。
- **晚一拍的部件，快的時候不能整張落後**（2026-10-01，Boss 跪下）：頭、布料照「上一張」算延遲，身體一張移 10px 以上時頭會和身體分開。延遲照舊，但和身體的差距要有上限（Boss：頭最多差 2px）。
- **要接回原本姿勢的動作，最後一張就是原本的姿勢**（2026-10-01，短僵直）：晚一拍的部件在最後一張還停在上一張，所以結尾要多留一張停住的姿勢；做不到（例如循環的布料相位）就寫成「在位移上限內接回」並量。
- **武器先到位，身體再下去**（2026-10-01，Boss 從肩上把劍插進地面再跪下）：武器往地面走的同時身體在降，武器還斜著時尖端就先碰到地、下一張再被拉回來（在地裡拖）。先讓武器到目的地（插好），再讓身體下去。
- **起手的長度看同一組連段**（第五版）：砍到之前的每一幀都會被讀成「還沒出手」。同一組連段裡某一段的起手特別長，看起來就是那一段前面停了一下；時間要改的時候，回頭跟機制一起改（例如縮短起手、讓上一段的收尾多留幾幀）。

### 4.3 姿勢語意：這個動作的重心在哪裡

- 參考圖的姿勢屬於待機動作，不可直接沿用到其他動作。每個動作都要重新判斷重心和站姿。例：走路時重心往前，腳要收到髖部下方，不可維持待機時外八、撐重心的站姿。
- 每個動作都要把姿勢目標量化（例如站距、靴子空隙、前傾角、抬腳高度）：
  - 以 `BODY_PX` 的比例寫進 `checks.py`，不要憑感覺取中間值。
  - 走路的數值在 README 交接筆記。
- 每個方向分開檢查。一個方向做對了，不代表其他方向也對。
- **四個面向是同一個 3D 姿勢**（2026-09-28，使用者）：依透視畫出每個方向該看到的東西。例：劍指向前方時，側面看到整把平伸的劍，正面只看到朝鏡頭的劍尖，背面只看到握劍的手和劍柄。不可為了某個方向好認，就把部件在那個方向轉成別的角度；好認要靠姿勢本身（重心、傾斜、手的位置）。
- **腳不可超出腿長**（2026-09-28）：側面每條腿從髖到踝不可長於腿本身（近側 ≤ 1.0 倍，遠側畫在後面 ≤ 1.1 倍），否則腿被拉長、貼地。這個角色的腿從髖到踝只有約 6px 高，骨盆每壓低 1px，腳能伸出的距離就少很多；站距、骨盆下降量這類目標要先和腿長一起驗算。
- **寬站姿的移動**：步長由移動速度和每張停幾幀決定，兩腳距離會在「站距 ± 步長」之間變化；站距寬的動作要用較短、較快的步伐，讓兩腳不會黏在一起、也不會拉長。
- **膝蓋不可高過髖**（第 3 批第二次修正）：側面的膝蓋至少在髖下方「髖到踝高度」的 10%。膝蓋和髖一樣高時，腿會畫成桌子（一條水平的大腿加一條垂直的小腿）或 M 字。骨架的腿骨要和實際站姿的腿長相當，不可比髖到踝長很多（腿骨越長，腳一往前膝蓋就頂得越高）。
- **四方向的腿高一致**：同一個姿勢，朝左、朝右按住時髖到踝的高度差 ≤ 1.5px。零件庫四個方向的關節點是各自量的，新姿勢要先核對，不可假設一致。
- **扭轉**（2026-09-29，第二版）：骨架不會扭腰時，上半身可以換成隔壁方向的圖表現扭轉；但手臂、劍、布料要照實際的扭轉角度擺（例如 45°），不是照畫出來的 90°。四個方向仍是同一個 3D 姿勢。
- **遠側被身體擋住**（第 3 批，使用者）：側面時，在身體另一側的手、武器，只看得到伸出身體輪廓外的部分（例如往前伸出的劍尖）。手臂移開後補上的底圖也是身體，不可讓後面的東西從那裡透出來。
- **正面／背面每條腿都看得到**：往遠處的腳在畫面上會變高，加上骨盆壓低、走路抬腳，腿可能變成 0；每條腿在畫面上至少 2px，靴子不可貼在腰甲上。這個角色正面的腿只有約 5px，前後跨步和壓低都要先驗算。
- **移動時重心在前**（2026-09-30，Boss 走路，使用者）：走、跑時身體要往前傾，不可維持站姿的直立只做上下起伏。側面看得到頭在腳的前方；正面／背面是胸口和頭在畫面上變低／變高。傾多少寫成檢查。
- **武器的拿法四個方向一致**（2026-09-30，使用者：「劍的透視四面記得做好」）：武器在動作裡的位置先定成一個 3D 姿勢（握點、指向、劍面朝哪），每個方向照同一套投影畫：朝鏡頭或背向鏡頭時變短，比腳更靠鏡頭的部分畫在腳底線以下、更遠的畫在以上（縱深 0.35 倍）。不可每個方向各擺一個看起來順眼的角度。
- **武器的拿法要合乎那個動作**（2026-09-30，Boss，使用者）：拿法要在每一種會用到它的動作裡都說得通（Boss 的劍拖在身後只在往前走時成立，後退、側移就不合理）。不可為了讓動作之間切換時武器不跳，就讓不合理的拿法沿用。最好一開始就選一個所有移動都成立、每一招也都能從它出手和收回的「備戰」拿法（Boss：使用者最後定為所有移動都把劍橫著扛在右肩上，出招後回到肩上）。
- **手屬於手臂，不屬於武器**（2026-09-30，Boss 拖劍，使用者）：武器換了角度，握它的拳頭跟著前臂（在前臂的延長線上），武器從拳頭裡穿過去；不可把站姿那個握著武器的拳頭連同武器一起轉。手臂要有手肘，不可一張圖從肩膀拉到手。看到拳頭的哪一面由握法決定（例：手垂著拖劍，劍身從拇指那一側往後伸，從背後看到的是拇指那一側）。
- **武器哪一面朝上、側對鏡頭時的厚度**（2026-09-30，Boss 扛劍）：寬的武器怎麼轉（平放還是立著）會決定每個方向看到多寬、擋住什麼，和握點、指向一起定，四個方向都試畫。平放的劍從側面只看得到厚度（縱深 0.35 倍），這是對的，不要為了好看在某個方向把它轉過來。轉動途中完全側對鏡頭的那幾張，畫出武器本身的厚度，不可縮成一條線。
- **兩隻手握同一把武器**（2026-10-01，Boss 攻擊）：畫面上兩隻拳頭的位置從武器算（一隻在握柄點，另一隻沿著武器的方向），手臂從各自的肩膀接過去；各自從肩膀投影時，畫出來的肩膀和投影差幾 px，拳頭就離開握柄。
- **側面是立面圖**（2026-10-01，Boss 攻擊）：側面的站姿兩邊肩膀一樣高，身上的點（拳頭、手肘）的畫面位置不照深度往上下移；只有武器、腳這類往鏡頭伸出去的方向照深度（0.35 倍）。照深度移的話，朝右和朝左同一個姿勢會不對稱。
- **劍面朝哪**（2026-10-01，Boss 攻擊）：揮砍時刃在前；慢慢移動、停住時劍面朝一個固定的方向（Boss：往前和往外之間 45°，和設計圖站姿一樣），四個方向都看得到劍面。只照移動方向轉時，劍面在不同方向一下寬一下窄。
- **大角度的轉身在正面／背面**（2026-10-02，Boss 單手快斬）：只把上身照圓柱轉，超過約 35° 細部就碎掉，而且還是讀不出轉。前傾的方向跟著身體轉（上身和頭往轉過去的那一邊倒，正面／背面看是往旁邊倒）、髖和前垂布跟著轉、兩條腿的上端往中間靠；側面的腿（平面裡解的）只轉一部分，避免兩個膝蓋一起往前折。
- **硬的部件整塊動，掛著的布跟著轉**（2026-10-02，Boss 單手快斬第三版，使用者）：肩甲這種護甲不跟著扭轉的胸口變形（在轉身的邊上會被擠扁、消失），整塊移到畫出來的肩膀上再轉；肩膀的位置照畫出來的胸口轉的角度算，不照 3D 的全部角度（兩者不一致時，肩甲會離開畫出來的肩膀）。身體轉過去時披風跟著轉成側面變窄，否則肩膀移開後背後一大片布看起來像缺了一塊。每一張量部件像素數和斷開的碎塊。
- **肩膀帶著上臂甩，不是手肘甩前臂**（2026-10-02，Boss 單手快斬第二版，使用者）：揮過去時上臂轉的角度要和前臂差不多（Boss：至少八成），手肘不在揮的途中打直或彎起；兩個關鍵姿勢之間拳頭的路線照著肩膀畫弧，不走直線（直線會靠近肩膀，手臂被擠彎）。肩甲、肩膀跟著上臂動：肩甲轉的基準是這一刀自己的中間，不可整段卡在上限不動；轉角在看不出前後的方向（手臂正對側邊）要淡出，不可一兩幀之間翻面。
- **單手揮砍：持劍的手臂伸直，空著的手留在自己那一側**（2026-10-02，Boss 單手快斬，使用者）：掃過去的那幾幀，持劍的手臂伸到接近全長（Boss：拳頭離肩膀 90% 以上），整隻手臂連劍一起繞著肩膀甩，重心跟著手臂往前；只靠前臂甩看起來沒有力。空著的手跟著身體轉、在自己那一側擺（往前、往後），不越過身體到持劍手那邊，也不往外平舉到肩膀高；手肘的方向放在身體的座標裡（身體轉多少，手肘跟著轉多少）。
- **停住的姿勢在每個方向都讀得出武器的方向**（2026-10-02）：武器伸向鏡頭時，側面只剩一把往下的劍（像垂在腿旁）；起手、揮完這種會停幾幀的姿勢，讓武器往後、放平。
- **插在地上的武器不動**（2026-10-01，Boss 跪地）：插進地面（或卡住）之後，身體再動（喘氣、被處決往後仰），武器停在原處（最多繞著入地點傾斜），握它的手臂伸長或縮短去接；不可整把跟著拳頭被拔出來又塞回去。
- **正面／背面要有讀得出的辨識點**（2026-10-01，Boss 跪姿）：側面一看就懂的姿勢，正面可能只是「變矮」。找出這個方向特有的線索並做出來（跪姿：兩膝分開、往前那隻腳因為比較靠鏡頭畫得比較低、披風攤在地上），在遊戲倍率看。
- 攻擊的站姿不可和待機、格擋一樣直：要寬步、前腳屈膝、重心壓低。
  - 站距、骨盆下降量、前膝角度都要有下限，寫進檢查。
  - 目標和設計圖（例如 C2、C3、D2）的輪廓疊圖對照後再訂。

### 4.4 技術品質（寫成程式自動檢查）

- **破洞**：頸部以下不可有破洞或透光縫。被輪廓包住的透明像素不可多於待機幀。
  - 頸部以上的羽飾碰到頭盔、圍出背景，不算破洞，也不列入自動檢查。
  - 交件時附上頸部以上的檢查圖，請使用者目視。
- **雜點**：不可有 1px 的裂縫，也不可有 1–2px 的孤立雜點（待機幀沒有的）。
- **底圖**：部件移開後露出的地方要有底圖，質感要和周圍一致，不可出現平坦的色塊。
  - 底圖只能墊在最底層，不可蓋住任何原圖像素。
- **圖層順序**：必須正確。例：正面的披風在身體後面。武器在身體前後切換的動作，圖層順序要能逐幀指定。
- **邊界**：腳和武器不可穿過地面（往鏡頭踏出的腳可以低 2px 以內）；所有幀都在畫格內；各方向的腳底基準線一致。
  - 骨架姿勢接到設計圖還原的姿勢（例如躺姿）時，兩邊比例可能不同：頭、軀幹、腳在接點兩端都要量（第 4 批：躺姿的腿長 30%，只量頭會漏掉腳跳 20px）。
- **上身轉不靠拉伸像素**（2026-10-01，Boss 攻擊）：欄被拉寬會把肩甲、布條抹成色塊。側面用整塊移動（近側肩甲前後移、遠側肩甲轉向鏡頭時露出來），正面／背面可以照圓柱轉，但只畫部分角度，並看細的部件有沒有被拉成一塊。
- **著地的是畫出來的部件**（2026-10-01）：跪、趴、躺的姿勢，膝蓋、手肘、身體貼地的那一面要量畫出來最低的一列在地面線上（不是關節點；零件在關節那一段比骨頭寬）。
- **幀間位移**：不可有突然的跳動。每個動作要訂出相鄰幀的位移上限（走路是 4px），攻擊等快速動作另訂。
- **高度用整數像素**（2026-09-29）：身體、骨盆的高度是半像素時，細條（圍巾、頭盔高光）會重新取樣，像素數多或少 10–40%。關鍵姿勢用整數；過渡幀是內插出來的，搜尋時把細節量一起算進去。
- **程式移動角色時（正面／背面）**：縱深在圖裡只有 0.35 倍，用「整個姿勢往後退」去抵銷程式的前進，身體會沉向鏡頭、腳卡在地面線下 2px、腿被壓扁。改成姿勢畫在自己的骨盆附近、整張圖在畫格裡平移（最多到畫格邊，88×72 上下各約 6px）。
  - 正面／背面那一列裡從側面畫的幀（例如轉身轉到一半）也一樣：程式往前的距離在那張圖裡變成縱深，要改用整張平移（第三版）。
- **細線條與高光**：
  - 劍身、1px 的羽飾或披風末梢不可旋轉後重新取樣，只做整數像素平移；需要不同角度時，用原圖的顏色另外畫零件。
  - 1px 的細條和單點高光在移動、旋轉、壓縮時不可消失：用正向搬移像素，兩個像素搶同一格時高光優先。
- **門檻來源**：以上以像素為單位的門檻，都從 `checks.py` 的尺寸常數 `BODY_PX = 40` 推算。新動作沿用同一組常數，不另寫固定數字。

### 4.5 讀得出來：武器與輪廓（寫成程式自動檢查）

- **武器對比**：劍身要和它背後的東西分得開。
  - 量劍身核心和周圍 2–3px 的亮度對比，最弱的一段也要過門檻。
  - 劍身擋在深色鎧甲前時，可以加亮劍身，或把兩排都畫成亮面。
  - 最容易出問題的是正面格擋（劍橫在胸前）。
- **同一組連段的每一段**（2026-09-29，使用者）：每段一條不同的揮劍線，全身的姿勢也不同，**只看剪影就分得出是第幾段**。檢查：每一對的起手與收尾，整個輪廓（含披風、羽飾：每段的布料甩法是設計的一部分）差 ≥ 12%；不含布料的數字另外列出。附上起手、收尾並排的剪影圖。
  - 第一版的條件「或看得到的劍有一半以上在別的地方」是後門：剪影只差 2–3% 的兩段也過，已拿掉（第二版）。
  - 剪影分不開、但差在顏色（例如正面對背面）的組合，列出來附圖請使用者決定。
  - 兩段輪流踏左腳、右腳時（2026-10-01，Boss 雙斬）：側面看腿只是左右對調，剪影一樣。步伐照每一段的份量分開（快的一段踏短、收尾的一段踏長），不是靠把姿勢扭成不一樣。
- **劍看得到**（第二版）：每個關鍵姿勢逐方向量劍露出多少像素。照透視被身體擋住的（遠側、背向鏡頭）是對的；舉在頭後、頭上的劍會被頭盔和羽飾整把擋住，要讀的劍往輪廓外伸。
- **輪廓差異**：意思不同的兩個姿勢（例如格擋與完美彈返），不靠特效也要一眼分得出來。
  - 比較兩者的剪影（不含披風、羽飾），差異比例要超過門檻。
  - 門檻用「相似的姿勢」校準，例如走路相鄰兩幀；門檻值和依據都寫在檢查裡。

### 4.6 設計圖有畫的姿勢

- 凡是設計圖有對應姿勢的動作，交件時必須附同比例、同姿勢的對照圖（設計圖小圖和成品並排，並疊上輪廓），並在報告中說明和設計圖的差異。
- 骨架做不出、設計圖又有畫的姿勢（例如倒地），要從設計圖還原原生像素，縮到定案尺寸，不可用站姿旋轉代替。

## 5. 審查方式

- **逐幀目視**：每一幀都要看，兩種倍率都要。放大 6 倍以上看細節，遊戲實際倍率（3 倍）看整體。
- **分方向產出**：每個方向單獨產出 GIF 和幀序列圖。
- **動作自然度**：不能只靠靜態圖判斷。
  - 列出逐部件的動作表：每幀的前傾角、手臂擺角、頭部延遲、兩腳的位置。
  - 對照 §4.2、§4.3 逐項確認。
  - 需要時加上洋蔥皮（前後幀疊在一起看）。
- **自動檢查**：§4.4 和量化目標寫進 `tools/sprite_rig/checks.py`，每次修改後重跑。
- **驗證檢查本身**：
  - 新檢查要先拿已知的情況試：該過的要過、該抓的要抓得到。
  - 輸出實際量到的數值，不能只印通過或失敗。
  - 一項檢查一個都量不到（例如條件從未成立）時，這項檢查本身就是錯的。
  - 標準答案不可從被檢查的程式讀取（例如拿動畫程式裡的延遲表去比對動畫的延遲），否則改了程式檢查也照樣過。要用獨立的標準：動作本身的其他部位、文件定案的數字（第 1 批）。
  - 量部件的位置、起伏時，用部件合成前的像素，不要用看得到的像素：被別的部件蓋住一排就會量錯（第 1 批）。
  - 量一個部件（例如布料揚起）要相對它所在的身體量，不要量絕對位置：身體同時在動（傾斜、下沉）時會被騙過（第 4 批）。
  - 循環的延遲要設計成量得出方向的：四階段循環裡晚兩個階段和早兩個階段一樣（第 4 批）。
  - 位移量螢幕上看到的位置：程式在動作中移動角色時（攻擊前進），要把畫面的移動算進去（第 2 批）。
  - 量法要對得上要量的東西（2026-09-30，Boss 扛劍）：「整張輪廓的變化」遇到細長、會掃動的部件會飽和（兩張不重疊就是固定的數字），量不出它動了多少；這種部件用位移量（劍尖每張移動多少），輪廓變化量它以外的部分。換量法時，把舊量法為什麼量不到、新的上限從哪裡來（例如主角的劍每步 20px 照身高換算）寫進檢查和進度檔。
  - 「輪廓變化的比例」不是位移的量法（2026-10-01，Boss 受擊）：窄的側面往後仰幾 px 就變 30%。位移量部件的位置（頭頂、頭的橫向位置，去掉武器和握它的手臂），比例只列出來。
  - 排除干擾時只排除干擾的那個部件（2026-10-01，Boss 攻擊）：量上身位置時去掉握柄附近一大圈，雙手舉到頭旁邊就連頭一起去掉；改成只去掉手臂骨頭附近的像素。
  - 為某個部件放寬的界線只套在那個部件上（2026-09-30，Boss）：例如「劍可以低於腳底線 20px」不可寫成「整張圖可以低 20px」，否則腳陷進地面也會過。
- **移動類的預覽**（第 3 批）：GIF 照程式速度在地面上實際移動（畫地面格線），滑不滑直接看得到；原地播放看不出腳滑。地面要照遊戲實際的速度動：俯視角的遊戲往上下走也是畫面上 1:1，不可為了讓腳看起來不滑把地面照 0.35 倍的縱深移動（2026-09-30，Boss 走路的預覽犯過，已改）。
- **接受的不合格寫成有紀錄的豁免**（第 3 批決定 10）：記下使用者核准時的實測值和決定編號；豁免的項目照樣印出數值，超過紀錄就重新失敗。檢查不可長期停在結束碼 1。
- **朝左、朝右並排比**（第 3 批）：兩個側面的骨架、零件庫都不對稱（關節點、靴子長度、近側是哪條腿），同一個姿勢要把兩邊放在一起看；一邊好看另一邊不好看，就找出差在哪裡，照好看那邊的畫法改。
- **手臂分段看**（2026-10-01，Boss 攻擊）：把上臂、前臂、拳頭、肩甲各塗一種顏色畫出整段動作，看上臂和肩甲有沒有跟著動；只有前臂、拳頭的顏色在變就是只有手肘在轉。
- **握武器的手要單獨看**（2026-09-30，Boss）：把手臂、拳頭、武器握把那一塊放大 4 倍以上，四個方向並排，站姿和動作中各一張。確認：哪隻手拿、拳頭有沒有接在前臂上、遠側的手有沒有被身體擋住。
- **腿要單獨看**（第 3 批第二次修正）：只畫腿的部件，加上髖、膝、踝的連線，放大 8 倍以上，四方向逐幀看。整張圖裡腿被身體、布料、劍擋住，常常只看得出一團。
- **放寬上限要有依據**（第二版）：任何位移上限、量化目標的放寬，都要引用使用者的決定（決定編號）；找不到就守原本的上限，改成多畫過渡幀或重排畫格。
- **調姿勢改善一組數字時，所有組都重跑**（第三版）：並排列出改前、改後的每一組，有一組變好、另一組變差（例如剪影 12% → 11%）就不算改善，不採用；交件紀錄照重跑後的數字寫。
- **不可為了過檢查扭曲姿勢**：檢查數字過不了時，先確認是姿勢真的不對，還是這項檢查量不到真正的差別（例如輪廓檢查看不到身體前面的劍）。自然的姿勢過不了，列出試過的做法，請使用者決定，不要硬加傾斜、轉動部件來過關。
- **看得出會突兀的先做好**（2026-09-30）：自審時自己列得出來的問題（例如兩個動作之間沒有過渡），屬於做得到的就先做，不要只寫在「請使用者看」。
- **明講限制**：沒辦法驗證的項目（例如實際播放時的節奏感）要在交件訊息裡明講。
- **舉一反三**：被糾正時，要檢查同一類問題有沒有出現在其他方向、其他部位。

## 6. 交件條件

- §3 都已確認，§4.1–§4.6 全部通過；沒通過的項目要有使用者的明確決定。
- **自己先看過、確定沒問題才交件**（2026-09-30，使用者明講）：每個方向、每一段都看過；握武器的手和武器放大、四方向並排看過（§5）；看得出的問題已經修掉。交件訊息要寫「自己看了哪些、確認了什麼」，不能只列檢查通過幾項。
- 交件訊息要列出：
  - 通過了哪些檢查（附實際數值）
  - 哪些項目沒辦法驗證
  - 和文件規格不同的地方
  - 頸部以上的目視檢查圖
  - 設計圖有對應姿勢的：同比例、同姿勢的對照圖，以及和設計圖的差異（§4.6）

## 7. 驗證有效的做法

程式、零件庫和細節在 `tools/sprite_rig/`，用法和交接筆記見該資料夾的 `README.md`。

- **外觀來自原圖像素**：從設計圖還原原生像素，不自己重畫角色。還原時要偵測不規則格線、校正非正方形像素、去背、統一色盤。
- **定案尺寸的零件庫**：每個視角各自縮到身體剛好 40px。
  - 縮小用區域平均加吸附色盤。
  - 面罩、鎖子甲這類辨識度高的細節，用記錄在程式裡的手工修補補回。
- **骨架動畫**：
  - 部件用零件庫像素，只改位置和角度。
  - 腿用原圖腿部的紋理貼到新姿勢，高光點另外放回。
  - 補好的身體墊在最底層。
- **像素保留**：正向搬移每個原圖像素，再補內部空隙；兩個像素搶同一格時高光優先；細線條只平移。
- **輔助圖**：
  - 部件切割疊圖（`inspect_parts.py`）。
  - 和參考圖同比例並排的比對圖。
  - 頸部以上的目視檢查圖。
